# 기능 명세서: 반복 이벤트 수정

## 📌 개요

### 기능 설명

사용자가 반복 이벤트(Recurring Event)를 수정하려고 할 때, "이 인스턴스만 수정" 또는 "전체 시리즈 수정" 중 선택할 수 있습니다.
사용자가 반복 이벤트를 편집 대상으로 선택하면 확인 다이얼로그가 나타나고, 사용자의 선택에 따라 시스템이 다른 작업을 수행합니다.

### 비즈니스 가치

- **사용자 가치**: 사용자는 반복 이벤트의 특정 인스턴스만 수정하여 일정을 유연하게 관리할 수 있음
- **비즈니스 가치**: 다양한 사용자의 수정 요구사항을 충족하여 사용자 만족도 향상
- **성공 지표**:
  - 반복 이벤트 수정 시 확인 다이얼로그 표시율: 100%
  - "이 인스턴스만 수정" 선택 시 단일 인스턴스 수정 성공률: > 95%
  - 반복 아이콘 제거 정확도: 100%

### 범위

- **포함**: 
  - 반복 이벤트 수정 시 확인 다이얼로그
  - "예" 선택 시 단일 인스턴스 수정 및 반복 아이콘 제거
  - "아니오" 선택 시 전체 시리즈 수정
- **제외**: 
  - 반복 이벤트 삭제 (향후 검토)
  - 예외 날짜 관리 UI (향후 검토)
  - 반복 규칙 수정 (반복 설정 변경은 별도 기능)

## 📋 상세 명세

### 기능 1: 반복 이벤트 수정 확인 다이얼로그

#### 설명

사용자가 반복 이벤트를 수정하려고 할 때 (`editEvent`가 호출될 때), 해당 이벤트가 반복 이벤트인 경우 확인 다이얼로그를 표시하여 사용자가 수정 범위를 선택하도록 합니다.

#### 입력

| 필드          | 타입      | 필수 | 제약조건                    | 기본값 | 예시                        |
| -------------- | --------- | -------- | ------------------------------ | ------- | ------------------------------ |
| editingEvent   | Event     | Y        | repeat.type !== 'none'         | -       | { id: 'evt_1', repeat: {...} } |
| updateData     | EventForm | Y        | 수정할 폼 입력 데이터  | -       | { title: '수정된 제목', ... } |

#### 처리 규칙

**주요 로직**:

1. IF `editingEvent.repeat.type !== 'none'` THEN
   - 확인 다이얼로그 표시
   - 다이얼로그 내용:
     - 제목: "반복 이벤트 수정"
     - 메시지: "이 인스턴스만 수정하시겠습니까?"
     - 두 개의 버튼: "예" (이 인스턴스만 수정), "아니오" (전체 시리즈 수정)
     - 취소 버튼 (다이얼로그 닫기)
2. ELSE IF `editingEvent.repeat.type === 'none'` THEN
   - 다이얼로그 표시 안 함
   - 즉시 수정 진행 (기존과 동일)
3. IF 사용자가 "예" 선택 THEN
   - `updateSingleInstance()` 호출
4. ELSE IF 사용자가 "아니오" 선택 THEN
   - `updateRecurringSeries()` 호출
5. ELSE IF 사용자가 "취소" 선택 THEN
   - 다이얼로그 닫기
   - 수정 취소

**비즈니스 규칙**:

- 규칙 1: 반복 이벤트(repeat.type !== 'none')인 경우에만 다이얼로그 표시
- 규칙 2: 다이얼로그는 한 번만 표시 (사용자 선택 대기)
- 규칙 3: 취소 시 기존 상태 유지 (수정 데이터 저장 안 함)

#### 출력

**성공 응답 - "예" 선택**:

```json
{
  "status": "success",
  "action": "single_instance_update",
  "data": {
    "updatedEvent": {
      "id": "evt_modified_123",
      "title": "수정된 제목",
      "repeat": { "type": "none" },
      ...
    }
  },
  "message": "이벤트가 수정되었습니다."
}
```

**성공 응답 - "아니오" 선택**:

```json
{
  "status": "success",
  "action": "series_update",
  "data": {
    "updatedEvents": [
      { "id": "evt_1", "title": "수정된 제목", ... },
      { "id": "evt_2", "title": "수정된 제목", ... },
      ...
    ]
  },
  "message": "모든 반복 이벤트가 수정되었습니다."
}
```

**취소 응답**:

```json
{
  "status": "cancelled",
  "message": "수정이 취소되었습니다."
}
```

#### 엣지 케이스

| #   | 케이스                      | 조건                        | 처리 방법                           | 우선순위 |
| --- | ------------------------- | -------------------------------- | ----------------------------------------- | -------- |
| 1   | 단일 이벤트 수정       | repeat.type === 'none'           | 다이얼로그 표시 안 함, 수정 진행 | 높음     |
| 2   | 사용자 취소              | 사용자가 취소 버튼 클릭        | 다이얼로그 닫기, 수정 데이터 초기화           | 높음     |
| 3   | 이미 수정된 인스턴스 | repeat.type === 'none'인 이벤트 | 다이얼로그 표시 안 함, 일반 수정 진행 | 중간   |
| 4   | 인스턴스가 하나만 남음 | 시리즈에 이 인스턴스만 존재     | "아니오" 선택을 일반 수정으로 처리      | 중간   |
| 5   | 다이얼로그가 이미 열림       | 다이얼로그 열림, 사용자가 다시 편집 시도 | 기존 다이얼로그 유지, 중복 생성 방지 | 중간   |
| 6   | 다이얼로그 열림 중 다른 이벤트 선택 | 다이얼로그 열림 중 다른 이벤트 클릭 | 기존 다이얼로그 닫기, 새 이벤트 수정 시작 | 낮음      |
| 7   | 네트워크 오류              | API 호출 실패                    | 오류 메시지 표시, 수정 데이터 보존 | 높음     |
| 8   | 동시 수정 시도 | 여러 탭에서 같은 이벤트 수정 | 마지막 수정만 반영 (서버 우선순위) | 낮음      |

#### 오류 처리

| 오류 코드 | 조건          | 사용자 메시지                  | 내부 로그                    | 복구 방법    |
| ---------- | ------------------ | ----------------------------- | ------------------------------- | ------------------ |
| E001       | 이벤트를 찾을 수 없음    | "이벤트를 찾을 수 없습니다"              | "event not found: [id]"         | 수정 취소      |
| E002       | 수정 권한 거부 | "수정할 수 없습니다"              | "update failed: [reason]"        | 수정 취소      |
| E003       | 유효성 검사 실패  | "입력을 확인해주세요"      | "validation failed: [field]"    | 오류 필드 표시   |
| E004       | 서버 오류       | "이벤트 저장에 실패했습니다"         | "server error: [status]"        | 재시도 버튼 표시  |

### 기능 2: 단일 인스턴스만 수정

#### 설명

사용자가 "예"를 선택하면, 선택된 이벤트만 수정되고 반복 시리즈에서 분리됩니다.
수정된 이벤트는 더 이상 반복 이벤트의 일부가 아니므로 반복 아이콘이 표시되지 않습니다.

#### 입력

| 필드         | 타입      | 필수 | 제약조건              | 기본값 | 예시                        |
| ------------- | --------- | -------- | ------------------------ | ------- | ------------------------------ |
| originalEvent | Event     | Y        | 반복 이벤트 (시리즈 멤버) | -      | { id: 'evt_1', repeat: {...} } |
| updateData    | EventForm | Y        | 수정할 폼 입력 데이터 | -      | { title: '수정된 제목', ... } |

#### 처리 규칙

**주요 로직**:

1. IF `originalEvent.repeat.type !== 'none'` THEN
   - 새 이벤트 생성 (원본 이벤트 복사)
     - `newEvent.id` = 새 UUID 생성 (`crypto.randomUUID()`)
     - `newEvent.repeat` = `{ type: 'none' }` (반복 정보 제거)
     - `newEvent`의 나머지 필드 = `updateData`로 수정
   - 원본 이벤트는 변경되지 않음 (시리즈의 다른 인스턴스는 변경 안 됨)
   - 수정된 새 이벤트 저장
   - 반복 아이콘 표시 결정:
     - `isRecurringEvent(newEvent)` === false (repeat.type === 'none')
     - 따라서 반복 아이콘 (`<Repeat />`)이 렌더링되지 않음
2. ELSE
   - 일반 수정 진행

**비즈니스 규칙**:

- 규칙 1: 단일 인스턴스 수정 시, 원본 시리즈에서 분리하기 위해 새 ID 할당
- 규칙 2: 반복 정보(repeat)를 `{ type: 'none' }`으로 설정하여 단일 이벤트로 변환
- 규칙 3: 원본 반복 이벤트 시리즈는 변경되지 않음 (다른 인스턴스 보존)
- 규칙 4: 수정된 이벤트는 캘린더에 반복 아이콘 없이 표시됨

#### 출력

**성공 응답**:

```json
{
  "status": "success",
  "action": "single_instance_update",
  "data": {
    "updatedEvent": {
      "id": "evt_new_123456",
      "title": "수정된 제목",
      "date": "2025-11-05",
      "startTime": "14:00",
      "endTime": "15:00",
      "repeat": {
        "type": "none"
      },
      ...
    }
  },
  "message": "이벤트가 수정되었습니다."
}
```

#### 엣지 케이스

| #   | 케이스                | 조건                    | 처리 방법                    | 우선순위 |
| --- | ------------------- | ---------------------------- | ---------------------------------- | -------- |
| 1   | 날짜 변경         | updateData.date 변경      | 새 날짜에 이벤트 생성           | 높음     |
| 2   | 시간 변경         | updateData.startTime/endTime 변경 | 시간만 수정                 | 높음     |
| 3   | 제목만 변경   | updateData.title만 변경 | 새 이벤트 생성, 다른 필드는 유지 | 중간   |
| 4   | 시리즈의 마지막 인스턴스 수정 | 시리즈에 이 인스턴스만 존재 | 선택적으로 원본 삭제, 새 이벤트 생성 | 중간   |
| 5   | 겹치는 이벤트    | 같은 시간에 다른 이벤트 존재 | 기존 겹침 확인 로직 적용 | 높음     |

#### 예시

**예시 1: 일반 케이스 - 제목 수정**

```
입력:
{
  originalEvent: {
    id: 'evt_1',
    title: '주간 회의',
    date: '2025-11-05',
    repeat: { type: 'weekly', interval: 1, ... }
  },
  updateData: {
    title: '주간 회의 (수정됨)',
    date: '2025-11-05',
    ...
  }
}

처리:
1. originalEvent가 반복 이벤트인지 확인 (type === 'weekly')
2. 새 이벤트 생성:
   - id: 'evt_new_789' (새 UUID)
   - title: '주간 회의 (수정됨)'
   - repeat: { type: 'none' } (반복 제거)
   - 기타 필드: updateData 값으로 설정
3. 새 이벤트 저장
4. 원본 시리즈는 변경 안 됨 (다른 주의 회의는 변경 안 됨)

출력:
{
  status: "success",
  data: {
    updatedEvent: {
      id: 'evt_new_789',
      title: '주간 회의 (수정됨)',
      repeat: { type: 'none' }
    }
  }
}

설명: 2025-11-05의 회의만 수정되어 반복 시리즈에서 분리되었습니다.
     다른 주의 회의 (2025-11-12, 2025-11-19, ...)는 변경되지 않았습니다.
```

**예시 2: 날짜 변경**

```
입력:
{
  originalEvent: {
    id: 'evt_1',
    date: '2025-11-05',
    repeat: { type: 'weekly', ... }
  },
  updateData: {
    date: '2025-11-06',  // 하루 연기
    ...
  }
}

처리:
1. 새 이벤트 생성 (2025-11-06)
2. repeat: { type: 'none' } 설정
3. 원본 2025-11-05 이벤트는 시리즈의 일부로 남음

출력:
{
  status: "success",
  data: {
    updatedEvent: {
      id: 'evt_new_789',
      date: '2025-11-06',
      repeat: { type: 'none' }
    }
  }
}

설명: 2025-11-05의 회의가 2025-11-06으로 변경되었지만,
     단일 인스턴스 수정이므로 반복 시리즈에서 분리되었습니다.
```

### 기능 3: 전체 반복 시리즈 수정

#### 설명

사용자가 "아니오"를 선택하면, 전체 반복 이벤트 시리즈가 수정됩니다.
같은 `repeat.id`를 가진 모든 이벤트가 동일하게 수정됩니다.

#### 입력

| 필드         | 타입      | 필수 | 제약조건              | 기본값 | 예시                        |
| ------------- | --------- | -------- | ------------------------ | ------- | ------------------------------ |
| originalEvent | Event     | Y        | 반복 이벤트 (시리즈 멤버) | -      | { id: 'evt_1', repeat: { id: 'repeat_123', ... } } |
| updateData    | EventForm | Y        | 수정할 폼 입력 데이터 | -      | { title: '수정된 제목', ... } |

#### 처리 규칙

**주요 로직**:

1. IF `originalEvent.repeat.id` 존재 THEN
   - `repeat.id`로 시리즈의 모든 이벤트 검색
   - 시리즈의 모든 이벤트에 대해:
     - 공통 필드 수정: title, description, location, category
     - 반복 규칙(repeat) 변경 시, 모든 인스턴스 재생성
     - 각 인스턴스의 날짜/시간은 반복 규칙에 따라 유지됨 (또는 규칙 변경 시 재계산)
   - 모든 이벤트 저장
2. ELSE IF `repeat.id` 없음
   - 일반 단일 이벤트 수정 진행 (하위 호환성)

**비즈니스 규칙**:

- 규칙 1: 같은 `repeat.id`를 가진 모든 이벤트가 동일하게 수정됨
- 규칙 2: 반복 규칙(repeat) 자체가 수정되면, 모든 인스턴스 재생성
- 규칙 3: 공통 필드(title, description, location, category)만 수정 가능
- 규칙 4: 각 인스턴스의 날짜는 반복 규칙에 의해 결정되므로, 직접 변경 불가
- 규칙 5: 수정 후에도 모든 이벤트는 반복 아이콘 계속 표시

#### 출력

**성공 응답**:

```json
{
  "status": "success",
  "action": "series_update",
  "data": {
    "updatedEvents": [
      {
        "id": "evt_1",
        "title": "수정된 제목",
        "date": "2025-11-05",
        "repeat": { "id": "repeat_123", "type": "weekly", ... }
      },
      {
        "id": "evt_2",
        "title": "수정된 제목",
        "date": "2025-11-12",
        "repeat": { "id": "repeat_123", "type": "weekly", ... }
      },
      ...
    ]
  },
  "message": "모든 반복 이벤트가 수정되었습니다."
}
```

#### 엣지 케이스

| #   | 케이스                  | 조건                    | 처리 방법                        | 우선순위 |
| --- | --------------------- | ---------------------------- | -------------------------------------- | -------- |
| 1   | 반복 규칙 변경 | updateData.repeat 변경    | 모든 인스턴스 재생성 (기존 먼저 삭제) | 높음     |
| 2   | 시리즈에 이벤트가 하나만 있음 | repeat.id로 찾은 이벤트가 하나만 있음 | 일반 수정으로 처리                 | 중간   |
| 3   | 일부 이벤트가 이미 삭제됨 | 시리즈 일부가 이미 삭제됨 | 남은 이벤트만 수정           | 중간   |
| 4   | 날짜 직접 변경 시도 | updateData.date 변경      | 무시 (반복 규칙이 날짜 결정) | 중간   |
| 5   | 시작 시간 변경    | updateData.startTime 변경 | 모든 인스턴스의 시간 동일하게 변경 | 높음     |

#### 예시

**예시 1: 일반 케이스 - 제목 수정**

```
입력:
{
  originalEvent: {
    id: 'evt_1',
    title: '주간 회의',
    repeat: { id: 'repeat_123', type: 'weekly', interval: 1, ... }
  },
  updateData: {
    title: '주간 정기 회의',
    ...
  }
}

처리:
1. repeat.id = 'repeat_123'으로 시리즈 검색
2. 시리즈 이벤트:
   - evt_1: 2025-11-05
   - evt_2: 2025-11-12
   - evt_3: 2025-11-19
   - ...
3. 모든 이벤트의 제목을 '주간 정기 회의'로 수정
4. 모든 이벤트 저장

출력:
{
  status: "success",
  data: {
    updatedEvents: [
      { id: 'evt_1', title: '주간 정기 회의', date: '2025-11-05', ... },
      { id: 'evt_2', title: '주간 정기 회의', date: '2025-11-12', ... },
      { id: 'evt_3', title: '주간 정기 회의', date: '2025-11-19', ... },
      ...
    ]
  }
}

설명: 모든 주의 회의 제목이 일괄 수정되었습니다.
```

### 기능 4: 반복 아이콘 표시/제거

#### 설명

이벤트가 반복 이벤트인지 여부에 따라 반복 아이콘 (`<Repeat />`)을 표시하거나 제거하는 기능입니다.

#### 입력

| 필드  | 타입  | 필수 | 제약조건              | 기본값 | 예시                          |
| ------ | ----- | -------- | ------------------------ | ------- | -------------------------------- |
| event  | Event | Y        | 수정된 이벤트            | -       | { id: 'evt_1', repeat: {...} } |

#### 처리 규칙

**주요 로직**:

1. IF `event.repeat.type !== 'none'` THEN
   - `isRecurringEvent(event)` === true
   - `<RecurringBadge event={event} />` 렌더링
   - 반복 아이콘 표시
2. ELSE IF `event.repeat.type === 'none'` THEN
   - `isRecurringEvent(event)` === false
   - `<RecurringBadge event={event} />` === null
   - 반복 아이콘 표시 안 함

**비즈니스 규칙**:

- 규칙 1: `repeat.type === 'none'`이면 반복 이벤트가 아님
- 규칙 2: "이 인스턴스만 수정" 선택 시 `repeat.type`이 `'none'`으로 변경되어 아이콘 제거됨
- 규칙 3: "전체 시리즈 수정" 선택 시 `repeat.type`이 유지되어 아이콘이 계속 표시됨
- 규칙 4: 아이콘 표시 상태는 실시간으로 반영됨 (재렌더링 시)

#### 출력

**아이콘 표시 상태**:

- `repeat.type !== 'none'`: 아이콘 표시 ✓
- `repeat.type === 'none'`: 아이콘 표시 안 함 ✗

#### 예시

**예시 1: "예" 선택 후 아이콘 제거**

```
수정 전:
{
  id: 'evt_1',
  title: '주간 회의',
  repeat: { type: 'weekly', ... }
}
→ 반복 아이콘 표시 ✓

수정 후 (단일 인스턴스 수정):
{
  id: 'evt_new_789',
  title: '주간 회의 (수정됨)',
  repeat: { type: 'none' }
}
→ 반복 아이콘 표시 안 함 ✗
```

**예시 2: "아니오" 선택 후 아이콘 유지**

```
수정 전:
{
  id: 'evt_1',
  title: '주간 회의',
  repeat: { id: 'repeat_123', type: 'weekly', ... }
}
→ 반복 아이콘 표시 ✓

수정 후 (전체 시리즈 수정):
{
  id: 'evt_1',
  title: '주간 정기 회의',
  repeat: { id: 'repeat_123', type: 'weekly', ... }
}
→ 반복 아이콘 계속 표시 ✓
```
