# 반복 일정: 삭제 기능 명세서

## 기능 개요

### 배경 설명

사용자가 반복 일정(Recurring Event)을 삭제하려 할 때, "이번 일정만 삭제할지 전체 반복 일정을 삭제할지" 선택할 수 있도록 해야 합니다. 사용자가 "네"을 선택하면 현재 날짜의 일정만 삭제되고, "아니오"를 선택하면 반복 시리즈 전체가 삭제될 수 있어야 합니다.

### 요구사항 정리

- **기본적 요구**: 반복 일정 삭제 시 사용자에게 선택지를 제공하고 선택에 따라 적절히 삭제 처리
- **사용자 경험**: 명확하고 직관적인 다이얼로그로 사용자의 의도를 정확히 파악
- **데이터 정합성**:
  - 단일 인스턴스 삭제 시 해당 인스턴스만 정확히 삭제: 100%
  - "네" 선택 시 다른 인스턴스는 유지 보장: > 95%
  - "아니오" 선택 시 전체 시리즈가 삭제됨을 보장: > 95%

### 범위

- **포함**:
  - 반복 일정 삭제 시 선택 다이얼로그 표시
  - "네" 선택 시 단일 인스턴스 삭제 (해당 날짜만 삭제)
  - "아니오" 선택 시 전체 반복 시리즈 삭제
  - 일반 일정 삭제 시 즉시 삭제 (다이얼로그 표시 안 함)
  - 삭제 성공 시 목록 새로고침 처리
- **제외**:
  - 삭제 취소(실행 취소 기능) 구현 (향후 추가 예정)
  - 삭제 전 확인 다이얼로그 (반복 일정만 대상)
  - 부분 수정 (특정 날짜 이후부터 삭제)
  - 삭제 이력 관리 UI

## 세부 기능 명세

### 기능 1: 반복 일정 삭제 시 선택 다이얼로그 표시

#### 설명

사용자가 삭제 버튼을 클릭했을 때 (`deleteEvent` 함수 호출 시), 해당 일정이 반복 일정인지 확인하고 반복 일정이라면 삭제 방식을 선택할 수 있는 다이얼로그를 표시합니다.

#### 입력값

| 파라미터 | 타입  | 필수 | 유효성 검사            | 기본값 | 예시                           |
| -------- | ----- | ---- | ---------------------- | ------ | ------------------------------ |
| event    | Event | Y    | repeat.type !== 'none' | -      | { id: 'evt_1', repeat: {...} } |

#### 처리 로직

**주요 흐름**:

1. IF `event.repeat.type !== 'none'` THEN
   - 선택 다이얼로그 표시
   - 다이얼로그 내용:
     - 제목: "반복 일정 삭제"
     - 설명문: "이번 일정만 삭제하시겠습니까?"
     - 선택 버튼: "네" (단일 인스턴스 삭제), "아니오" (전체 시리즈)
2. ELSE IF `event.repeat.type === 'none'` THEN
   - 다이얼로그 표시 없이 즉시
   - 일반 삭제 로직 실행 (기존 `deleteEvent` 로직)
3. IF 사용자가 "네" 선택 THEN
   - `deleteSingleInstance(event)` 실행
4. ELSE IF 사용자가 "아니오" 선택 THEN
   - `deleteRecurringSeries(event)` 실행

**예외 처리**:

- 경우 1: 반복 일정(repeat.type !== 'none')이 아니면 다이얼로그 생략
- 경우 2: 취소버튼 클릭 시 아무 작업 없음 (원래 화면 유지)
- 경우 3: 삭제 중 오류발생 시 에러 토스트 표시 (롤백 처리 불필요)

#### 출력값

**정상 응답 - "네" 선택 (단일 인스턴스 삭제)**:

- 해당 날짜 일정만 삭제
- 다른 날짜의 동일 반복 일정은 유지됨
- 성공 메시지: "일정이 삭제되었습니다."
- 일정 목록에서 해당 날짜 항목만 제거
- 화면 자동으로 업데이트 완료 (새로고침 필요없음)

**정상 응답 - "아니오" 선택 (전체 시리즈 삭제)**:

- 해당 반복의 모든 인스턴스 삭제됨
- 성공 메시지: "반복 일정 전체가 삭제되었습니다."
- 일정 목록에서 관련된 모든 날짜 항목이 제거됨

#### 엣지 케이스

| #   | 상황                                         | 발생 조건                                       | 예상 동작                                    | 우선순위 |
| --- | -------------------------------------------- | ----------------------------------------------- | -------------------------------------------- | -------- |
| 1   | 반복 인스턴스가 하나만 남은 경우 (마지막)    | 삭제 대상이 해당 시 리즈의 마지막 인스턴스일 때 | 전체 삭제와 동일하게 처리 (시리즈 자체 삭제) | Medium   |
| 2   | 동시 여러 사용자 삭제 시도                   | 동시 요청/충돌이 발생한 경우                    | 먼저 완료된 요청: "반복 일정 삭제완료"       | High     |
| 3   | 네트워크 오류 발생                           | API 통신 실패                                   | 에러 토스트: "삭제 실패. 다시 시도해주세요"  | High     |
| 4   | 다이얼로그 표시 중 다른 화면 이동 시도       | 화면 전환 이벤트                                | 다이얼로그 닫고 화면 전환 허용 (삭제 취소)   | Medium   |
| 5   | 삭제 대상이 과거 이벤트일 경우 (1년 이전 등) | 오래된 일정 삭제                                | 정상 삭제 처리와 동일하게 처리               | Low      |

#### 에러 처리

| 에러 코드 | 에러 조건                 | 사용자 메시지                        | 개발자 로그                  | 에러 레벨   |
| --------- | ------------------------- | ------------------------------------ | ---------------------------- | ----------- |
| E001      | 일정이 존재하지 않을 경우 | "해당 일정을 찾을수없습니다"         | "Event not found: {id}"      | 경고 레벨   |
| E002      | 삭제 API 실패             | "삭제 실패. 다시 시도해주세요"       | "Delete failed: {error}"     | 오류 레벨   |
| E003      | 네트워크 오류             | "네트워크 오류. 연결을 확인해주세요" | "Network error: {error}"     | 오류 레벨   |
| E004      | 반복정보 ID 없음          | "반복 일정 정보가 올바르지 않습니다" | "Repeat ID missing: {event}" | 치명적 레벨 |

### 기능 2: 단일 인스턴스만 삭제

#### 설명

사용자가 "네"를 선택한 경우, 해당 날짜에 해당하는 일정 인스턴스만 삭제하고 나머지 반복 일정은 유지합니다.

#### 입력값

| 파라미터 | 타입  | 필수 | 유효성 검사            | 기본값 | 예시                           |
| -------- | ----- | ---- | ---------------------- | ------ | ------------------------------ |
| event    | Event | Y    | repeat.type !== 'none' | -      | { id: 'evt_1', repeat: {...} } |

#### 처리 로직

**주요 흐름**:

1. IF `event.repeat.id`가 존재 THEN
   - 해당 `event.id`만 삭제
   - API 호출: `DELETE /api/events/{event.id}`
2. 삭제 완료 후:
   - 일정 목록 최신화 호출 (`fetchEvents()`)
   - 성공 토스트 표시: "일정이 삭제되었습니다."
   - 다이얼로그 닫기

**예외 처리**:

- 경우 1: 해당 인스턴스가 이미 삭제된 경우 에러 표시 후 목록만 새로고침
- 경우 2: 서버 오류 시 에러 토스트 표시하고 기존 화면 유지 (롤백불필요)

#### 출력값

**정상 응답**:

```json
{
  "status": "success",
  "action": "single_instance_delete",
  "message": "일정이 삭제되었습니다."
}
```

**UI 변화**:

- 일정 목록에서 해당 날짜 항목만 사라짐
- 다른 날짜의 동일 반복 일정은 그대로 표시됨
- 성공 토스트 하단에 표시

#### 예시

**예시 1: 단일 삭제 - 매주 반복되는 회의**

```
입력값:
- Event: {
    id: "evt_2025_11_15",
    title: "주간 회의",
    date: "2025-11-15",
    repeat: {
      id: "repeat_123",
      type: "weekly",
      interval: 1
    }
  }

처리 과정:
1. 선택 다이얼로그 표시: "이번 일정만 삭제하시겠습니까?"
2. 사용자가 "네" 선택
3. API 호출: DELETE /api/events/evt_2025_11_15
4. 삭제 성공 응답
5. 일정 목록 새로고침

결과:
- 일정 목록에서 "2025-11-15 주간 회의" 사라짐
- "2025-11-08 주간 회의", "2025-11-22 주간 회의" 등은 유지
- 성공 메시지: "일정이 삭제되었습니다."

의미: 해당 주의 회의만 취소되고 다른 주의 회의는 계속 예정되어
      있다는 것을 사용자가 명확히 인지할수있습니다.
```

### 기능 3: 전체 반복 시리즈 삭제

#### 설명

사용자가 "아니오"를 선택한 경우, 해당 반복의 모든 인스턴스를 삭제합니다.

#### 입력값

| 파라미터  | 타입   | 필수 | 유효성 검사            | 기본값 | 예시                           |
| --------- | ------ | ---- | ---------------------- | ------ | ------------------------------ |
| event     | Event  | Y    | repeat.type !== 'none' | -      | { id: 'evt_1', repeat: {...} } |
| repeat.id | string | Y    | 반복 시리즈 식별자     | -      | "repeat_123"                   |

#### 처리 로직

**주요 흐름**:

1. IF `event.repeat.id`가 존재 THEN
   - 해당 반복의 모든 인스턴스 일괄 삭제
   - API 호출: `DELETE /api/recurring-events/{repeat.id}`
2. 삭제 완료 후:
   - 일정 목록 최신화 호출 (`fetchEvents()`)
   - 성공 토스트 표시: "반복 일정 전체가 삭제되었습니다."
   - 다이얼로그 닫기

**예외 처리**:

- 경우 1: `repeat.id`가 없는 경우 에러 처리 필요
- 경우 2: 일부 인스턴스만 삭제된 경우 처리 방안

#### 출력값

**정상 응답**:

```json
{
  "status": "success",
  "action": "series_delete",
  "message": "반복 일정 전체가 삭제되었습니다."
}
```

**UI 변화**:

- 해당 반복의 모든 인스턴스가 일정 목록에서 사라짐
- 성공 토스트 하단에 표시

#### 예시

**예시 1: 전체 삭제 - 매주 반복되는 회의**

```
입력값:
- Event: {
    id: "evt_2025_11_15",
    title: "주간 회의",
    date: "2025-11-15",
    repeat: {
      id: "repeat_123",
      type: "weekly",
      interval: 1
    }
  }

처리 과정:
1. 선택 다이얼로그 표시: "이번 일정만 삭제하시겠습니까?"
2. 사용자가 "아니오" 선택
3. API 호출: DELETE /api/recurring-events/repeat_123
4. 삭제 성공 응답 (전체 시리즈)
5. 일정 목록 새로고침

결과:
- 해당 반복의 모든 인스턴스 삭제됨:
  - "2025-11-08 주간 회의" 사라짐
  - "2025-11-15 주간 회의" 사라짐
  - "2025-11-22 주간 회의" 사라짐
  - ... (향후 예정된 모든 반복 인스턴스)
- 성공 메시지: "반복 일정 전체가 삭제되었습니다."

의미: 해당 회의 시리즈 자체가 더이상 필요없어서 완전히
      종료시킵니다.
```

## 구현 기술스택

### 프론트엔드 컴포넌트

- **다이얼로그 컴포넌트 이름**: 새로운 다이얼로그 생성 필요 (`RecurringEventDeleteDialog`)
- **호출 위치 설명**: 기존 `deleteEvent` 함수 내부 (일정 삭제 버튼 클릭 시)

### 기술 스택

- **React**: UI 컴포넌트
- **Material-UI**: Dialog 컴포넌트
- **API**:
  - `DELETE /api/events/{id}` (단일 인스턴스 삭제)
  - `DELETE /api/recurring-events/{repeatId}` (전체 시리즈 삭제)

### 구현 방안

- 기존 `RecurringEventUpdateDialog` 컴포넌트를 참고하여 새로운 `RecurringEventDeleteDialog` 생성
- `useEventOperations` 훅에 `deleteSingleInstance`, `deleteRecurringSeries` 함수 추가
- `App.tsx`에서 삭제 시 다이얼로그 표시 로직 추가
