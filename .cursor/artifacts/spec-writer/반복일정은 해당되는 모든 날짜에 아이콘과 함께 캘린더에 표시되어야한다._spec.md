# 기능 명세: 반복일정은 해당되는 모든 날짜에 아이콘과 함께 캘린더에 표시되어야한다.

## 개요
반복 규칙을 가진 일정은 캘린더에서 보이는 기간 내 모든 해당 날짜에 표시되어야 하며, 반복 일정임을 식별할 수 있도록 일정 셀(혹은 이벤트 배지)에 반복 아이콘이 함께 렌더링되어야 한다.

## 범위
- 캘린더 보기: 월/주/일 보기 공통
- 데이터 소스: 저장된 이벤트(단일 + 반복), 반복 규칙, 종료일, 예외일
- 출력: 가시 기간 내 인스턴스 리스트 + 각 인스턴스의 표시 속성(아이콘 표시 여부)

## 용어
- 반복 이벤트: 반복 규칙을 보유한 원본 이벤트
- 인스턴스: 반복 규칙으로 생성된 개별 표시 일정
- 예외일(Exceptions): 해당 날짜의 인스턴스를 제외하는 로컬 날짜 목록(YYYY-MM-DD)

## 상세 명세
1) 인스턴스 생성
- 가시 기간(현재 뷰에 보이는 날짜 범위) 내에서만 반복 인스턴스를 생성한다.
- 규칙: daily/weekly/monthly/yearly, interval, 요일 세트, 월 N번째 요일 등 기존 규칙을 준수한다.
- repeatEnd가 있으면 해당 날짜를 초과하는 인스턴스를 생성하지 않는다(당일 포함 여부는 프로젝트 표준에 따르되 기본 포함).
- exceptions 목록에 포함된 날짜는 생성하지 않는다.

2) 표시 규칙
- 인스턴스는 단일 이벤트와 동일한 시간대(start/end 시각)로 표시한다.
- 반복 이벤트에서 생성된 인스턴스에는 반복을 나타내는 아이콘을 함께 렌더링한다.
  - 아이콘 표기 방법: 이벤트 배지 우측 상단에 `repeat` 아이콘(예: 🔁 또는 프로젝트의 SVG 아이콘) 표시.
  - 접근성: 아이콘에 aria-label="반복 일정"을 제공한다.
  - 툴팁(선택): hover 시 "반복 일정" 텍스트 노출.
- 동일 날짜에 단일/반복 이벤트가 함께 있을 수 있으며, 중첩 규칙은 기존 레이아웃 로직을 따른다.

3) 성능/상태 업데이트
- 뷰 전환/이동 시에만 재계산한다.
- 동일 입력에 대한 재계산은 메모이제이션 고려(선택).

## 수용 기준(검증 기준)
1. 월 보기에서 "매주 월/수 10:00-11:00" 반복 일정이 있으면 해당 달의 모든 월/수에 인스턴스가 보이고, 각 인스턴스에 반복 아이콘이 표시된다.
2. 주 보기에서 "매월 15일 09:00-10:00" 일정은 15일이 포함된 주에만 보이고, 해당 인스턴스에 반복 아이콘이 표시된다.
3. repeatEnd를 초과한 날짜에는 인스턴스가 생성되지 않는다(당일 포함 규칙에 맞게 동작).
4. exceptions에 포함된 날짜는 보이지 않는다.
5. 단일 이벤트와 반복 이벤트가 같은 날에 모두 존재해도 각각 올바르게 표시되며, 반복 이벤트에만 반복 아이콘이 표시된다.
6. 이전/다음으로 뷰를 이동하면 가시 기간 내 인스턴스와 아이콘 표시가 정확히 업데이트된다.

## 테스트 아이디어
- weekly 규칙(요일 세트), monthly 규칙(일자/N번째 요일), daily/yearly 각각 최소 한 케이스
- interval 적용(격주/격월) 시 아이콘 포함 표시 확인
- exceptions/ repeatEnd 경계 확인(표시/비표시 + 아이콘 존재 여부)
- 접근성: 아이콘 aria-label 존재 확인

## 구현 힌트
- 인스턴스 생성은 기존 `utils/repeatRuleGenerator.ts` 또는 동등 유틸을 사용
- 표시 계층에서 인스턴스의 `isRecurring=true`와 같은 플래그를 내려 아이콘 조건부 렌더링
- 컴포넌트 예시: 이벤트 배지 컴포넌트 내 아이콘 슬롯 추가

## 완료 조건
- 수용 기준 1~6 충족
- 테스트 케이스 3개 이상 설계 가능 수준으로 명세 충족
