## 1. Quick Reference Template

> **사용 시점**: 단순하고 명확한 기능, 빠른 피드백이 필요한 경우

### 특징
- ✅ 간결하고 핵심만 담음
- ✅ 1-2페이지 분량
- ✅ 단순한 CRUD나 유틸리티 기능에 적합
- ✅ 빠른 이해와 구현이 목표

#### ✅ 좋은 예시
```markdown
# 기능 명세: 사용자 검색

## 📋 요약
이름 또는 이메일로 사용자를 검색하여 목록을 반환하는 기능

**사용자**: 관리자
**목적**: 빠른 사용자 조회 및 관리

---

## 🎯 핵심 규칙

### 입력
| 항목 | 타입 | 필수 | 제약 조건 |
|------|------|------|-----------|
| query | string | Y | 2-50자, 공백 허용 |
| searchType | enum | N | 'name' 또는 'email', 기본값 'name' |

### 처리 규칙
1. IF query.length < 2 THEN 에러 "최소 2자 이상 입력하세요"
2. IF searchType === 'email' THEN 이메일 형식 검증
3. ELSE 이름 부분 일치 검색 (대소문자 무시)

### 출력
- **성공**: 사용자 목록 배열 (최대 100개)
- **실패**: 에러 메시지

| 케이스 | 처리 방법 |

| 100개 초과 | 처음 100개만 반환, "결과가 많습니다" 경고 |
| 특수문자 입력 | 특수문자도 검색어로 허용 (SQL 인젝션 방어) |

### Feature Specification 작성 예시

#### ❌ 나쁜 예시
```markdown
# 기능 명세: 일정 등록

사용자가 일정을 등록할 수 있다.
제목과 날짜를 입력받는다.
```

#### ✅ 좋은 예시
```markdown
# 기능 명세: 일정 등록

## 📌 개요

### 기능 설명
사용자가 제목, 날짜, 시간, 설명을 입력하여 새로운 일정을 생성하고 저장하는 기능입니다. 
일정은 캘린더에 표시되며, 알림 설정이 가능합니다.

### 비즈니스 가치
- **사용자 가치**: 중요한 일정을 쉽게 기록하고 관리하여 시간 관리 효율성 향상
- **비즈니스 가치**: 사용자 참여도 증가 및 일일 활성 사용자(DAU) 증가
- **성공 지표**: 
  - 일일 평균 일정 생성 수 > 2개/사용자
  - 일정 생성 완료율 > 95%

### 범위
- **포함**: 단일 일정 생성, 기본 알림 설정, 유효성 검증
- **제외**: 반복 일정 (v2.0), 여러 명 초대 (v2.0), 캘린더 동기화 (v3.0)

---

## 🎯 상세 명세

### 기능 1: 일정 정보 입력

#### 설명
사용자가 일정의 기본 정보(제목, 날짜, 시간, 설명)를 입력하는 폼을 제공합니다.

#### 입력
| 항목 | 타입 | 필수 | 제약 조건 | 기본값 | 예시 |
|------|------|------|-----------|--------|------|
| title | string | Y | 1-100자, 특수문자 허용 | - | "팀 회의" |
| date | date | Y | 오늘 이후, ISO 8601 | - | "2025-10-30" |
| startTime | time | Y | HH:mm 형식 | - | "14:00" |
| endTime | time | N | startTime 이후 | startTime + 1시간 | "15:00" |
| description | string | N | 최대 500자 | "" | "Q4 계획 논의" |
| reminder | enum | N | 'none','10min','30min','1hour','1day' | '30min' | '1hour' |

#### 처리 규칙

**주요 로직**:
1. IF title.length < 1 THEN
   - 에러 표시: "제목을 입력하세요"
   - 저장 버튼 비활성화
2. IF date < 오늘 날짜 THEN
   - 에러 표시: "과거 날짜는 선택할 수 없습니다"
   - 날짜 선택 초기화
3. IF endTime <= startTime THEN
   - 자동으로 endTime = startTime + 1시간
   - 정보 메시지: "종료 시간이 자동 조정되었습니다"
4. IF 동일 시간에 일정 존재 THEN
   - 경고 표시: "이미 일정이 있습니다. 계속하시겠습니까?"
   - 사용자 확인 후 저장 허용
5. ELSE
   - 모든 검증 통과
   - 저장 진행

**비즈니스 규칙**:
- 규칙 1: 일정은 최소 10분 단위로 설정 (startTime, endTime)
- 규칙 2: 하루 최대 20개 일정까지 생성 가능
- 규칙 3: 제목은 중복 허용 (동일 제목의 일정 여러 개 가능)
- 규칙 4: 알림은 일정 시작 시간 기준으로 계산

#### 출력

**성공 응답**:
```json
{
  "status": "success",
  "data": {
    "id": "evt_1234567890",
    "title": "팀 회의",
    "date": "2025-10-30",
    "startTime": "14:00",
    "endTime": "15:00",
    "description": "Q4 계획 논의",
    "reminder": "1hour",
    "createdAt": "2025-10-28T10:30:00Z"
  },
  "message": "일정이 저장되었습니다"
}
```

**실패 응답**:
```json
{
  "status": "error",
  "code": "VALIDATION_ERROR",
  "message": "제목을 입력하세요",
  "field": "title"
}
```

#### 엣지 케이스

| # | 케이스 | 발생 조건 | 처리 방법 | 우선순위 |
|---|--------|-----------|-----------|----------|
| 1 | 빈 제목 입력 | title.trim() === "" | 에러 메시지, 저장 불가 | High |
| 2 | 과거 날짜 선택 | date < today | 에러 메시지, 날짜 초기화 | High |
| 3 | 종료시간 < 시작시간 | endTime <= startTime | 자동 조정 (startTime + 1h) | Medium |
| 4 | 시간 중복 | 동일 시간에 다른 일정 존재 | 경고 후 저장 허용 | Medium |
| 5 | 매우 긴 제목 | title.length > 100 | 100자에서 자르고 경고 | Medium |
| 6 | 특수문자 제목 | 이모지, HTML 태그 포함 | 허용하되 XSS 방어 | High |
| 7 | 하루 20개 초과 | 같은 날짜 20개 일정 초과 | 에러 "일일 한도 초과" | Low |
| 8 | 오프라인 상태 | 저장 시 오프라인 | 로컬 임시 저장 | High |
| 9 | 자정 시간 | 00:00 선택 | 허용, 다음날 00:00으로 처리 | Low |
| 10 | 윤년 2월 29일 | 윤년이 아닌 해 | 윤년 검증, 에러 처리 | Low |

#### 에러 처리

| 에러 코드 | 발생 조건 | 사용자 메시지 | 내부 로그 | 복구 방법 |
|-----------|-----------|---------------|-----------|-----------|
| E001 | title 빈 값 | "제목을 입력하세요" | "title validation failed: empty" | 사용자 입력 유도 |
| E002 | date < today | "과거 날짜는 선택할 수 없습니다" | "date validation failed: past date" | 날짜 초기화 |
| E003 | 저장 실패 | "저장 실패. 다시 시도해주세요" | "save error: [reason]" | 재시도 버튼 표시 |
| E004 | 일일 한도 초과 | "하루 최대 20개까지 등록 가능합니다" | "daily limit exceeded: 20" | 기존 일정 삭제 유도 |

#### 예시

**예시 1: 정상 케이스 - 기본 일정 생성**
```
입력:
{
  "title": "팀 회의",
  "date": "2025-10-30",
  "startTime": "14:00",
  "endTime": "15:00",
  "description": "Q4 계획 논의",
  "reminder": "1hour"
}

처리 과정:
1. title 검증 통과 (5자)
2. date 검증 통과 (미래 날짜)
3. startTime < endTime 확인
4. 중복 일정 없음 확인
5. 로컬 스토리지에 저장
6. 알림 스케줄 등록 (13:00)

출력:
{
  "status": "success",
  "data": {
    "id": "evt_1234567890",
    ...
  },
  "message": "일정이 저장되었습니다"
}

설명: 모든 검증을 통과하여 정상적으로 일정이 생성되고, 
      1시간 전 알림이 예약됩니다.
```

**예시 2: 엣지 케이스 - 시간 자동 조정**
```
입력:
{
  "title": "점심 약속",
  "date": "2025-10-30",
  "startTime": "12:00",
  "endTime": "11:30",  // 시작 시간보다 이른 종료 시간
  "description": "",
  "reminder": "30min"
}

처리 과정:
1. title 검증 통과
2. date 검증 통과
3. endTime < startTime 감지
4. endTime 자동 조정: 12:00 + 1시간 = 13:00
5. 정보 메시지 표시
6. 저장 진행

출력:
{
  "status": "success",
  "data": {
    "endTime": "13:00"  // 자동 조정됨
  },
  "message": "종료 시간이 자동 조정되었습니다"
}

설명: 논리적으로 불가능한 시간이 입력되면 자동으로 
      합리적인 값으로 조정하여 사용자 경험을 개선합니다.
```

**예시 3: 에러 케이스 - 과거 날짜**
```
입력:
{
  "title": "지난 회의",
  "date": "2025-10-20",  // 현재: 2025-10-28
  "startTime": "14:00",
  "endTime": "15:00"
}

처리 과정:
1. title 검증 통과
2. date < today 감지
3. 즉시 에러 반환
4. 저장 중단

출력:
{
  "status": "error",
  "code": "E002",
  "message": "과거 날짜는 선택할 수 없습니다",
  "field": "date"
}

설명: 과거 날짜에 일정을 생성할 수 없도록 하여 
      데이터 무결성을 유지합니다.
```
