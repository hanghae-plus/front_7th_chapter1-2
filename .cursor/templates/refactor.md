# Refactoring Templates

## 템플릿 선택 가이드

### 언제 어떤 템플릿을 사용할까?

| 템플릿                        | 사용 시점                     | 작성 시간 | 상세도     |
| ----------------------------- | ----------------------------- | --------- | ---------- |
| **Quick Refactoring Report**  | 단순한 개선, 빠른 리뷰 필요   | 5-10분    | ⭐⭐       |
| **Detailed Refactoring Plan** | 대규모 개선, 상세 계획 필요   | 20-30분   | ⭐⭐⭐⭐⭐ |
| **Code Review Report**        | 코드 분석 및 개선점 도출 필요 | 15-20분   | ⭐⭐⭐⭐   |

## 1. Quick Refactoring Report Template

> **사용 시점**: 단순한 개선사항, 빠른 피드백이 필요한 경우

### 특징

- ✅ 간결하고 핵심만 담음
- ✅ 1-2페이지 분량
- ✅ 소규모 리팩토링에 적합
- ✅ 빠른 승인 및 실행이 목표

### 템플릿

```markdown
# 리팩토링 리포트: [대상 파일/기능]

## 📊 발견된 이슈

| 분류    | 이슈        | 우선순위 |
| ------- | ----------- | -------- |
| [분류1] | [이슈 설명] | H/M/L    |
| [분류2] | [이슈 설명] | H/M/L    |
| [분류3] | [이슈 설명] | H/M/L    |

---

## 🎯 개선 계획

### 1. [개선 항목 1]

- **현재**: [현재 상태]
- **변경**: [변경 내용]
- **이유**: [개선 이유]

### 2. [개선 항목 2]

- **현재**: [현재 상태]
- **변경**: [변경 내용]
- **이유**: [개선 이유]

---

## 📈 예상 효과

- ✅ [효과 1]
- ✅ [효과 2]
- ✅ [효과 3]

---

## ⚠️ 위험도

- **변경 범위**: [파일 수] 파일, [줄 수] 줄
- **위험도**: Low / Medium / High
- **테스트**: [테스트 존재 여부]

**Status**: Refactoring Plan Complete - Awaiting User Approval

💡 승인하시려면 "승인" 또는 "ok"라고 말씀해주세요.
```
