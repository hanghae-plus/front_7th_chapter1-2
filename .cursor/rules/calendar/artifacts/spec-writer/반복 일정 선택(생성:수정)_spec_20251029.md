# 기능 명세: 반복 일정 선택(생성/수정)

## 📌 개요

### 기능 설명

사용자가 일정 생성 또는 수정 시 반복 유형을 선택하여 일정을 반복 생성하는 기능입니다. 반복 유형은 매일, 매주, 매월, 매년을 지원하며, 특정 규칙에 따라 존재하지 않는 날짜에 대한 대체 생성은 하지 않습니다.

### 비즈니스 가치

- **사용자 가치**: 반복되는 업무/약속을 자동화하여 입력 시간을 절감하고 누락을 방지
- **비즈니스 가치**: 일정 활용도 증가, 일일 활성 사용자(DAU) 및 접속 빈도 향상
- **성공 지표**:
  - 반복 일정 생성 성공률 ≥ 99%
  - 반복 일정 수정 후 재생성 정확도 ≥ 99%
  - 사용자 불만(오동작/예상과 다름) 비율 ≤ 1%

### 범위

- **포함**:
  - 반복 유형 선택: daily, weekly, monthly, yearly
  - 반복 규칙에 따른 인스턴스(occurrence) 생성 규칙
  - 반복 종료 조건 및 생성 한도
  - “반복일정은 일정 겹침을 고려하지 않는다” 규칙 반영
- **제외**:
  - “시리즈 전체 vs 이후만 적용 vs 단일 인스턴스만 적용” 수정 스코프 UI
  - 예외 날짜(스킵/이동) 및 개별 인스턴스 커스터마이징
  - 외부 캘린더 동기화, 서버 동기화
  - 초대/공유/권한

## 🎯 상세 명세

### 기능 1: 반복 유형 및 규칙 설정

#### 설명

일정 폼에서 반복 유형을 선택하고, 시작일을 기준으로 반복 인스턴스를 계산합니다. 모든 시간/날짜는 KST(UTC+9) 기준, ISO 8601 형식을 사용합니다.

#### 입력

| 항목            | 타입                 | 필수 | 제약 조건                                                   | 기본값   | 예시         |
| --------------- | -------------------- | ---- | ----------------------------------------------------------- | -------- | ------------ | -------- | --- | --------- |
| startDate       | date (ISO 8601, KST) | Y    | 오늘 또는 미래 날짜                                         | -        | "2025-03-31" |
| startTime       | time (HH:mm)         | Y    | 00:00–23:59                                                 | -        | "14:00"      |
| endTime         | time (HH:mm)         | N    | startTime < endTime                                         | start+1h | "15:00"      |
| repeat.enabled  | boolean              | Y    | true일 때에만 반복 생성                                     | false    | true         |
| repeat.type     | enum                 | Y    | 'daily'                                                     | 'weekly' | 'monthly'    | 'yearly' | -   | "monthly" |
| repeat.count    | number               | N    | 1–1000 (count 또는 until 중 하나 필수)                      | -        | 12           |
| repeat.until    | date (ISO 8601, KST) | N    | startDate ≤ until ≤ startDate+10y, count와 동시에 지정 불가 | -        | "2026-03-31" |
| repeat.interval | number               | N    | 1–12, 기본 1(매 1일/1주/1달/1년)                            | 1        | 1            |

메모:

- count와 until은 상호 배타적. 둘 다 없으면 에러.
- interval은 지원하되 기본값 1만 명시적으로 사용(고급 옵션이지만 제한 없이 허용).

#### 처리 규칙

**공통 로직:**

1. IF repeat.enabled === false THEN 반복 생성하지 않음.
2. IF repeat.enabled === true AND (repeat.count is empty AND repeat.until is empty) THEN 에러 "반복 종료 조건을 지정하세요".
3. IF repeat.count AND repeat.until 둘 다 지정됨 THEN 에러 "count와 until 중 하나만 지정하세요".
4. IF endTime <= startTime THEN endTime = startTime + 1시간.
5. 반복 인스턴스 생성 시 “일정 겹침 무시”:
   - 기존/자기 생성 인스턴스와 시간이 겹치더라도 생성 차단/조정/경고를 하지 않음.

**반복 유형별 로직:**

- daily:

  1. 기준: startDate의 연-월-일을 기준으로 매 interval일 마다 생성.
  2. 시간대: startTime–endTime 그대로 복사.

- weekly:

  1. 기준: startDate의 요일을 기준으로 매 interval주마다 동일 요일에 생성.
  2. 예: startDate가 2025-10-29(수)이고 interval=1이면, 매주 수요일 생성.

- monthly:

  1. 기준: startDate의 “일(day-of-month)”을 기준으로 매 interval개월 뒤 같은 “일”에 생성.
  2. 존재하지 않는 날짜는 “대체하지 않고 스킵”:
     - 31일 시작이면 31일이 존재하는 달에만 생성. 30일/28일/29일인 달은 건너뜀.
     - 30일 시작이면 30일이 없는 2월은 건너뜀.
  3. 시간대: startTime–endTime 그대로 복사.

- yearly:
  1. 기준: startDate의 월-일을 기준으로 매 interval년 뒤 동일 월-일에 생성.
  2. 윤년 2월 29일 시작 시 “대체하지 않고 스킵”:
     - 윤년이 아닌 해에는 생성하지 않음. 2월 28일 또는 3월 1일로 대체하지 않음.
  3. 기타 날짜는 동일 월-일 그대로 생성.

**종료 조건 계산:**

- count가 주어진 경우: startDate 포함 총 count개 생성(1회차= startDate).
- until이 주어진 경우: startDate부터 until 날짜 “이하”에 해당하는 인스턴스를 모두 생성.
- 안전 한도: 생성 상한 10,000회. 초과 가능성이 감지되면 에러 "반복 횟수가 너무 큽니다(최대 10,000)".

#### 출력

- 성공:
  - 생성 규칙 메타와 함께 인스턴스 배열(각 인스턴스의 id는 저장 시점에서 부여될 수 있음)
  - 예:

```json
{
  "status": "success",
  "data": {
    "repeat": {
      "enabled": true,
      "type": "monthly",
      "interval": 1,
      "count": 3,
      "anchor": "2025-01-31"
    },
    "occurrences": [
      "2025-01-31T14:00:00+09:00",
      "2025-03-31T14:00:00+09:00",
      "2025-05-31T14:00:00+09:00"
    ]
  }
}
```

- 실패:

```json
{
  "status": "error",
  "code": "VALIDATION_ERROR",
  "message": "반복 종료 조건을 지정하세요",
  "field": "repeat"
}
```

#### 엣지 케이스

| #   | 케이스                  | 발생 조건                    | 처리 방법                                   | 우선순위 |
| --- | ----------------------- | ---------------------------- | ------------------------------------------- | -------- |
| 1   | 월말 31일 시작          | startDate=31일, monthly      | 31일 있는 달에만 생성, 다른 달은 스킵       | High     |
| 2   | 2월에 30·31일 없음      | startDate=30/31일, monthly   | 2월은 스킵                                  | High     |
| 3   | 윤년 2/29 시작, yearly  | startDate=02-29, yearly      | 윤년에만 생성, 대체 불가                    | High     |
| 4   | until과 count 동시 지정 | repeat.count & repeat.until  | 에러 반환                                   | High     |
| 5   | 반복 겹침 무시          | 동일 시간대 다른 일정 존재   | 생성 강행, 충돌 경고/조정 없음              | Medium   |
| 6   | endTime ≤ startTime     | 사용자가 역전 시간 입력      | endTime = startTime+1h로 자동 조정          | Medium   |
| 7   | 매우 큰 반복 횟수       | 계산 결과 10,000회 초과 가능 | 에러 "반복 횟수가 너무 큽니다(최대 10,000)" | Medium   |
| 8   | interval > 1            | interval=2 등                | 규칙대로 계산(매 2일/2주/2달/2년)           | Low      |

#### 에러 처리

| 에러 코드            | 발생 조건                             | 사용자 메시지                                    | 내부 로그                         | 복구 방법                  |
| -------------------- | ------------------------------------- | ------------------------------------------------ | --------------------------------- | -------------------------- |
| REPEAT_INVALID_SCOPE | count와 until 동시 지정               | "count와 until 중 하나만 지정하세요"             | "repeat scope conflict"           | 하나만 남기고 재시도       |
| REPEAT_MISSING_SCOPE | count와 until 모두 누락               | "반복 종료 조건을 지정하세요"                    | "repeat scope missing"            | count 또는 until 입력 유도 |
| REPEAT_TOO_MANY      | 생성 상한 초과(>10,000회)             | "반복 횟수가 너무 큽니다(최대 10,000)"           | "repeat expansion exceeded limit" | 범위 축소(기간/횟수 감소)  |
| TIME_INVALID_RANGE   | endTime ≤ startTime                   | "종료 시간이 자동으로 1시간 뒤로 조정되었습니다" | "endTime auto adjusted (+1h)"     | 자동 조정 후 계속          |
| DATE_INVALID_PAST    | startDate가 과거(정책에 따라 금지 시) | "과거 날짜는 선택할 수 없습니다"                 | "startDate in the past"           | 날짜 재선택                |

#### 예시

**예시 1: 월말 31일 시작, monthly, count=3**

```
입력:
startDate: 2025-01-31, startTime: 14:00, endTime: 15:00
repeat: { enabled: true, type: "monthly", interval: 1, count: 3 }

처리:
- 2025-01-31 생성
- 2025-02-31 없음 → 스킵
- 2025-03-31 생성
- 2025-04-31 없음 → 스킵
- 2025-05-31 생성 (총 3회 달성)

출력:
occurrences: [
  "2025-01-31T14:00:00+09:00",
  "2025-03-31T14:00:00+09:00",
  "2025-05-31T14:00:00+09:00"
]
설명: "마지막 날 대체 없음. 31일이 있는 달에만 생성"
```

**예시 2: 윤년 2/29 시작, yearly, until=2029-03-01**

```
입력:
startDate: 2024-02-29, startTime: 09:00
repeat: { enabled: true, type: "yearly", until: "2029-03-01" }

처리:
- 2024-02-29 생성
- 2025-02-29 없음 → 스킵
- 2026-02-29 없음 → 스킵
- 2027-02-29 없음 → 스킵
- 2028-02-29 생성 (윤년)
- 2029-02-29 없음 → 스킵 (until 범위 내)

출력:
occurrences: [
  "2024-02-29T09:00:00+09:00",
  "2028-02-29T09:00:00+09:00"
]
설명: "2/29는 윤년에만 생성. 대체 없음"
```

**예시 3: weekly, 수요일 기준**

```
입력:
startDate: 2025-10-29(수), startTime: 10:00
repeat: { enabled: true, type: "weekly", interval: 1, count: 3 }

처리:
- 매주 수요일 3회 생성: 10/29, 11/05, 11/12

출력:
occurrences: [
  "2025-10-29T10:00:00+09:00",
  "2025-11-05T10:00:00+09:00",
  "2025-11-12T10:00:00+09:00"
]
설명: "startDate의 요일이 앵커"
```

**예시 4: daily, 겹침 무시**

```
입력:
startDate: 2025-11-01, 08:00–09:00
repeat: { enabled: true, type: "daily", count: 2 }
(이미 2025-11-02 08:30–09:30에 다른 일정 존재)

처리:
- 11/01, 11/02 모두 생성 (겹침 고려하지 않음)

출력:
성공, 경고/차단 없음
설명: "반복일정은 일정 겹침을 고려하지 않는다"
```

#### 제약사항

- 모든 날짜/시간은 KST(UTC+9), ISO 8601 형식 사용.
- count 또는 until 중 하나는 필수.
- 최대 생성 상한 10,000회.
- 존재하지 않는 날짜에 대한 대체 생성(말일 대체, 2/28·3/1 대체 등) 금지.

#### 의존성

- 달력 날짜 유효성 검증 유틸리티(`isValidDate`, `isLeapYear`)
- 날짜 연산 유틸리티(`addDays`, `addWeeks`, `addMonths`, `addYears`)
- 시간 포맷/파싱 유틸리티(ISO 8601, HH:mm)

## ✅ 검증 기준

### 기능 테스트

- [ ] monthly: 31일 시작 시 31일 있는 달에만 생성
- [ ] yearly: 2/29 시작 시 윤년에만 생성
- [ ] weekly: 시작 요일 기준 반복 정확
- [ ] daily: 반복 생성 간 충돌 무시됨
- [ ] count 기준: startDate 포함 정확히 N회 생성
- [ ] until 기준: until 날짜 “이하”만 생성
- [ ] endTime 자동 조정(≤ startTime 입력 시 +1h)
