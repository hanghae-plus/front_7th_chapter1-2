# Step: PRD 및 요구사항 확인

````xml
<step>
  <purpose>
    PRD 문서를 읽고 구현해야 할 요구사항을 정확히 파악합니다.
    이후 디버깅 시 PRD와 코드를 비교할 기준을 마련합니다.
  </purpose>

  <how-to>
    <action n="1">
      <do>PRD 문서 읽기</do>
      <detail>
        docs/prd/ 디렉토리에서 최신 버전의 PRD 문서를 찾아 읽습니다:

        ```bash
        ls -lt docs/prd/ | head -5
        cat docs/prd/prd-{{기능명}}-v{{최신버전}}.md
        ```

        확인할 내용:
        1. **배경과 문제 정의**: 왜 이 기능이 필요한가?
        2. **목표**: 무엇을 달성해야 하는가?
        3. **범위**: 포함/제외 범위는?
        4. **사용자 시나리오**: 사용자가 어떻게 사용하는가?
        5. **기능 요구사항**: 구체적으로 무엇을 구현해야 하는가?
      </detail>
    </action>

    <action n="2">
      <do>예외 규칙 및 경계값 케이스 파악</do>
      <detail>
        PRD에서 특별히 명시된 예외 규칙과 경계값 케이스를 찾아 정리합니다:

        예시:
        - 매월 31일 반복 시 31일이 없는 달(2월, 4월, 6월, 9월, 11월)은 건너뜀
        - 윤년 2월 29일 반복 시 평년에는 생성되지 않음
        - 시작일 > 종료일인 경우 에러 처리
        - interval이 0 또는 음수인 경우 에러 처리

        이러한 규칙들을 메모해두고, 구현 시 반드시 반영해야 합니다.

        체크리스트:
        - [ ] 예외 규칙이 명시되어 있는가?
        - [ ] 경계값 케이스가 정의되어 있는가?
        - [ ] 에러 처리 방법이 명시되어 있는가?
        - [ ] 비즈니스 로직의 우선순위가 명확한가?
      </detail>
    </action>

    <action n="3">
      <do>비기능 요구사항 확인</do>
      <detail>
        성능, 보안, 접근성 등 비기능 요구사항이 있는지 확인합니다:

        확인할 내용:
        - 성능 요구사항 (응답 시간, 처리량 등)
        - 데이터 검증 규칙
        - 에러 메시지 표시 방법
        - 사용자 피드백 방법

        예시:
        - 일정 생성 시 1초 이내 응답
        - 잘못된 날짜 입력 시 명확한 에러 메시지 표시
        - 성공 시 스낵바로 알림
      </detail>
    </action>

    <action n="4">
      <do>요구사항 체크리스트 작성</do>
      <detail>
        PRD를 바탕으로 구현해야 할 항목을 체크리스트로 정리합니다:

        예시:
        ```markdown
        ## 구현 체크리스트

        ### 기본 기능
        - [ ] 매일 반복 일정 생성
        - [ ] 매주 반복 일정 생성
        - [ ] 매월 반복 일정 생성
        - [ ] 매년 반복 일정 생성

        ### 예외 규칙
        - [ ] 매월 31일 규칙 (31일 없는 달 건너뜀)
        - [ ] 윤년 2월 29일 규칙 (평년 건너뜀)

        ### 에러 처리
        - [ ] 시작일 > 종료일 검증
        - [ ] interval 유효성 검증
        - [ ] 필수 필드 검증

        ### UI/UX
        - [ ] 성공 시 스낵바 표시
        - [ ] 에러 시 명확한 메시지
        ```

        이 체크리스트는 구현 중 참고하고, 완료 후 모든 항목이 체크되었는지 확인합니다.
      </detail>
    </action>

    <action n="5">
      <do>불명확한 요구사항 식별</do>
      <detail>
        PRD에서 불명확하거나 모호한 부분이 있는지 확인합니다:

        확인할 내용:
        - 구현 방법이 명확하지 않은 요구사항
        - 상충되는 요구사항
        - 누락된 것으로 보이는 요구사항

        불명확한 부분이 있다면:
        1. 다른 에이전트의 worklog 확인 (docs/worklog/)
        2. 테스트 케이스 문서 확인 (docs/testcases/)
        3. 기존 코드 패턴 참고
        4. 그래도 불명확하면 worklog에 기록하고 합리적인 가정 하에 구현

        예시:
        ```markdown
        ## 불명확한 요구사항

        1. "반복 일정이 겹칠 경우" 처리 방법이 명시되지 않음
           → 가정: 겹쳐도 모두 생성 (일반적인 캘린더 동작)

        2. "종료일이 없는 무한 반복" 지원 여부 불명확
           → 가정: 현재 버전에서는 미지원 (PRD 범위 외)
        ```
      </detail>
    </action>
  </how-to>

  <constraints>
    <constraint>PRD의 최신 버전을 참고할 것</constraint>
    <constraint>예외 규칙과 경계값 케이스를 빠짐없이 파악할 것</constraint>
    <constraint>불명확한 요구사항은 worklog에 기록할 것</constraint>
    <constraint>요구사항 체크리스트를 작성할 것</constraint>
  </constraints>

  <success-criteria>
    <criterion>PRD 문서를 읽고 이해함</criterion>
    <criterion>예외 규칙과 경계값 케이스를 파악함</criterion>
    <criterion>요구사항 체크리스트를 작성함</criterion>
    <criterion>불명확한 요구사항을 식별하고 기록함</criterion>
  </success-criteria>
</step>
````
