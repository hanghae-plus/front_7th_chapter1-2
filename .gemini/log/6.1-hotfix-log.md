# Story 6.1-hotfix-log.md (달력 뷰 반복 확장)

## [로그 분석 결과 by Off코치]

### 1. 통합 테스트 RED 단계

- **상태:** RED (실패)
- **실패 로그:**
    1.  `Encountered two children with the same key, \`1\`.` (React 경고)
    2.  `AssertionError: expected ... to have a length of 7 but got 6` (테스트 실패)
- **원인 분석:**
    1.  **Key 경고:** `expandRecurringEvents` 함수가 원본 이벤트의 `id`를 그대로 복사하여, `map` 렌더링 시 중복 `key`가 발생함. 이는 **프로덕션 코드의 버그**임.
    2.  **테스트 실패:** 테스트 코드의 논리적 오류. 이벤트 시작일(`2025-09-29`)과 캘린더 뷰의 현재 주(9/28~10/4)를 고려했을 때, 이벤트가 표시되는 날은 6일이 맞으나 테스트가 7일을 기대함.
- **조치 제안 (Brian에게):**
    1.  `App.tsx`의 모든 `map` 렌더링에서 `key`를 `event.id` 대신 `${event.id}-${event.date}`로 수정.
    2.  테스트 코드의 기대값을 `7`에서 `6`으로 수정.

### 2. 통합 테스트 GREEN 단계 (회귀 버그 발생)

- **상태:** RED (실패)
- **실패 로그:**
    1.  `Found multiple elements with the text: 매일 반복 회의`
    2.  `Unable to find an element with the text: 검색 결과가 없습니다.`
- **원인 분석:**
    1.  **`multiple elements` 오류:** `useSearch` 훅을 수정하면서, 우측 목록(`event-list`)까지 확장된 이벤트 목록을 사용하게 되어 발생한 **회귀 버그**.
    2.  **`검색 결과` 오류:** 위 버그를 수정하는 과정에서, `listEvents`가 더 이상 날짜 범위로 필터링되지 않도록 잘못 수정하여 발생한 2차 **회귀 버그**.
- **조치 제안 (Brian에게):**
    1.  `useSearch` 훅이 `listEvents`(검색어+날짜 필터링)와 `calendarEvents`(확장) 두 종류의 목록을 반환하도록 리팩토링.
    2.  `App.tsx`의 각 뷰가 목적에 맞는 목록을 사용하도록 수정.

### 3. 최종 GREEN 단계

- **상태:** GREEN (성공)
- **검토 내용:** Brian이 제안된 모든 조치를 수행하여 회귀 버그를 해결하고, 모든 테스트가 통과함을 확인. Hotfix 기능 구현이 완료됨.
