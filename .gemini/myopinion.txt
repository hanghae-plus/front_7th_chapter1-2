1. 구조 설계
- 비매드 매서드 구조를 차용하자
    - Analyst(스티브잡스) : PRD문서 생성/업데이트
    - Architecture(빌게이츠) : 아키텍처 정리 문서 생성/업데이트
    - Scrum Master(일론머스크) : TDD 기반의 테스트 스토리 문서 생성/업데이트
    - 개발자(윤지훈) : TDD 기반 테스트코드 작성 (Red-Green-Factor 패턴 적용 / 각 패턴마다 커밋), 테스트 스토리마다 1~2개의 테스트는 “내”가 작성해볼 수 있도록 빈칸으로 만듦
    - QA(준일코치) : 결과 분석 및 피드백 + 비어있던 테스트 코드 정답 작성(‘내’가 작성한 소스는 주석처리)

2. 규칙 정리
- 공통
    - 테스트 파일을 제외한 모든 문서의 확장자는 .md로 통일한다.
    - 각 에이전트들은 본인에게 부여된 명세파일에 내용을 1순위로 참고한다.
    - 각 에이전트들에 대한 명세 파일에는 이름, 역할, 목표, 규칙, 참고할 문서 경로, 산출물 경로, 산출물 포맷, 산출물의 좋은 예시, 산출물의 나쁜 예시가 포함돼야 한다.
    - 각 에이전트들은 이전 혹은 TDD 사이클 (프롬프트에 명시된) 내 특정 단계의 에이전트가 만든 산출물을 반드시 참고한다.
    - 각 에이전트들은 정형화된 output 포맷을 유지해야 한다.
    - 각 에이전트들은 필요시 정형화된 input 포맷을 유지해야 한다.
    - 각 에이전트들은 본인의 업무 명세를 숙지하고, 기동 결과가 각 명세 내용을 잘 적용했는지에 대한 결과를 체크박스로 시각화 해준다.
    - 각 에이전트들은 프롬프트 완료 후에 체크리스트에 기반하여 결과물에 대한 점수를 산출해낸다.
    - ‘개발자’와 ‘QA’를 제외한 나머지 에이전트들은 프롬프트에 명령이 없다면 본인에게 지정된 산출물과 본인의 명세 파일을 제외한 모든 소스들을 수정해선 안된다.
    - ‘개발자’와 ‘QA’는 기존의 코드를 수정해선 안된다.
- 개별
    - Analyst : PRD 생성
    - Scrum Master : PRD와 과제 명세서를 기반으로 테스트 스토리 제작 / 명세서의 메인 토픽 하나당 하나의 스토리 파일이 생성돼야함 / 개발자가 테스트코드를 작성 할 수 있는 디스크립션 예제가 작성돼있어야함
