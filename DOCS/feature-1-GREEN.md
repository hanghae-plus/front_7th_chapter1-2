# [GREEN] Feature 1: 반복 유형 선택 - 최소 구현

## 관련 요구사항

- 1. 반복 유형 선택 (recurring type selection)
  - 31일 선택 시: 매월 31일에만 일정 생성(30/28/29일 대체 금지)
  - 2/29 선택 시: 윤년 2월 29일에만 일정 생성
  - 반복 일정은 겹침 허용

## 목적

- RED 단계에서 작성한 실패 테스트를 통과시키기 위한 **최소 구현(GREEN)**을 적용한다.

## 변경 파일

- src/utils/eventUtils.ts
  - `generateRecurrences(params)` 함수 추가 (최소 기능)

## 구현 요약

- 타입: `monthly`, `yearly`에 한해 RED 테스트를 통과시키는 최소 로직만 구현
- 월간(monthly)
  - 시작일이 31일이면 31일이 존재하는 달(1,3,5,7,8,10,12)에만 생성
  - interval 간격으로 월을 전진함
- 연간(yearly)
  - 시작일이 2/29이면 윤년에만 생성(대체 금지)
  - interval 간격으로 연도를 전진함
- 종료 범위: `end` 날짜를 초과하지 않도록 생성 제한
- 겹침 처리: 별도 중복 제거 로직 없음(요구사항에 따라 허용)

## 결정성/범위

- 현재 테스트가 요구하는 최소 규칙(31일, 2/29, 겹침 허용)만 충족
- 기타 일반 케이스(예: 30일 시작, 주간/일간 등)는 후속 요구/테스트에서 확장

## 한계 및 리팩토링 후보(차후 REFACTOR 단계)

- 규칙 분리: 31일 규칙, 윤년 규칙 등 순수 함수 추출
- 인터페이스 개선: clock 주입/최대 종료일(2025-12-31) 상한 적용 위치 명확화
- 반복 타입 전반(Weekly/Daily) 일반화 및 테스트 추가 대응

## 검증 체크리스트

- [ ] RED 테스트 3건 전부 통과
- [ ] 월 31일: 31일 있는 달만 포함
- [ ] 연 2/29: 윤년만 포함, 대체 금지
- [ ] 종료일 경계 초과 생성 없음
- [ ] 겹침 허용 로직 유지(중복 제거 없음)
