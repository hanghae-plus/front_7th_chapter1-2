# [RED] Feature 1: 반복 유형 선택 - 단일 책임 테스트 작성

## 관련 요구사항

- 1. 반복 유형 선택 (recurring type selection)
  - 일정 생성/수정 시 다음 반복 유형 중 하나를 선택할 수 있다: 매일, 매주, 매월, 매년
  - 31일 선택 시: 매월 31일에만 일정 생성(30/28/29일 대체 금지)
  - 2/29 선택 시: 윤년 2월 29일에만 일정 생성
  - 반복 일정은 겹침 허용

## 산출 목적

- 위 요구사항에 대응하는 핵심 “반복 유형 선택” 동작에 대한 실패 테스트(RED) 작성을 목표로 한다.
- 일정 생성 시, 반복 유형이 정상 인식 및 처리되는지 검증
- 특수 규칙(31일, 2/29일, 겹침 허용)에 대한 단일 책임 테스트 작성

## 실제 작성 결과 요약

- src/**tests**/unit/recurrenceUtils.spec.ts
  - "generateRecurrences" 유틸 함수에 대한 단위 테스트 3건 작성(초기 단계엔 임시 함수명)
  1. 매월 31일 반복 선택 시 1, 3, 5, 7, 8, 10, 12월 31일 일정만 생성되는지 검증(나머지 달은 생성 불가)
  2. 연 2/29 반복 시 윤년(2024, 2028)만 포함 (다른 해는 생성 금지)
  3. 기존 일정과 겹치더라도 중복 허용되어 생성됨을 검증(중복 제거 불필요)
- 테스트 설명 및 주석 모두 한국어로 명확히 작성(가독성/도메인 추적성 확보)
