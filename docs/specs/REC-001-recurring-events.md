# REC-001: 반복 일정 기능

## 1. 개요

- 목적: 일정 생성/수정/삭제 과정에서 반복 일정을 지원하고, 캘린더 뷰에 반복 일정을 구분 표시한다.
- 배경: 사용자 편의를 위해 빈번한 일정(매일/매주/매월/매년)의 자동 생성이 필요하며, 단일/전체 수정과 삭제의 구분 처리가 요구됨.

## 2. 범위(Scope)

- 포함:
  - 반복 유형 선택: 매일, 매주, 매월, 매년
  - 매월 31일 규칙: 31일에만 생성(해당 월에 31일이 없는 경우 생성되지 않음)
  - 윤년 2월 29일 규칙: 매년 2월 29일에만 생성(윤년에만 생성)
  - 반복일정은 일정 겹침 고려 제외
  - 캘린더 뷰에서 반복 일정 아이콘으로 구분 표시
  - 반복 종료: 종료일 없음(무한 반복) 또는 특정 날짜까지(≤ 2025-12-31, 하드 제한)
  - 반복 일정 수정/삭제 시 단일 vs 전체 처리 분기
- 제외(명시적 비범위):
  - 사용자 정의 주기(예: 평일만, 격주, N번째 요일 등)
  - 반복 종료 옵션 중 “횟수로 제한” 등 다른 종료 방식
  - 예외 날짜 관리(스킵/개별 예외 목록) 및 시리즈 일부만 유지하는 고급 기능

## 3. 요구사항

### 3.1 기능 요구사항(FRs)

- FR-1: 일정 생성/수정 시 반복 유형(매일/매주/매월/매년)을 선택할 수 있어야 한다.
- FR-2: 매월 31일 선택 시, 31일에만 생성되며 31일이 없는 월에는 생성되지 않아야 한다.
- FR-3: 매년 2월 29일 선택 시, 윤년에만 2월 29일에 생성되어야 한다.
- FR-4: 반복 일정은 일정 겹침(오버랩)을 판단 대상에서 제외해야 한다.
- FR-5: 캘린더 뷰에서 반복 일정에 아이콘을 표시해 단일 일정과 구분되어야 한다.
- FR-6: 종료 옵션을 지원해야 한다: 종료일 없음(무한 반복) 또는 특정 날짜까지(≤ 2025-12-31, UI/저장 검증 하드 제한).
- FR-7: 반복 일정 수정 시 사용자에게 “해당 일정만 수정하시겠어요?”를 묻고, 예=단일 수정, 아니오=전체 수정을 수행해야 한다.
- FR-8: 단일 수정 선택 시 해당 인스턴스는 단일 일정으로 분리되며 반복 아이콘이 사라져야 한다.
- FR-9: 전체 수정 선택 시 반복 속성은 유지되며 반복 아이콘도 유지되어야 한다.
  - FR-10: 반복 일정 삭제 시 사용자에게 “해당 일정만 삭제하시겠어요?”를 묻고, 예=해당 일정만 삭제, 아니오=전체 삭제를 수행해야 한다. 전체 삭제 시 단일로 분리된 인스턴스는 삭제 대상에서 제외되어야 한다.
  - FR-11: 반복 일정의 시작시간/종료시간은 단일 일정과 동일한 규칙을 따른다.
  - FR-12: 단일로 분리된 인스턴스는 이후 전체 수정/삭제의 영향을 받지 않는다(완전 독립).

## 4. 사용자 시나리오 & 플로우

- 시나리오 A(생성):
  1. 일정 생성 → 2) 반복 유형 선택(매일/매주/매월/매년) → 3) 종료일 없음 선택 또는 종료일 선택(≤ 2025-12-31) → 4) 저장 → 5) 캘린더에 반복 아이콘으로 표시
- 시나리오 B(수정):
  1. 반복 일정 인스턴스 클릭 → 2) “해당 일정만 수정하시겠어요?” 질문 → 3) 예=단일 수정(해당 인스턴스만 단일 일정으로 분리, 아이콘 제거), 아니오=전체 수정(시리즈 유지, 아이콘 유지) → 4) 저장
- 시나리오 C(삭제):
  1. 반복 일정 인스턴스 클릭 → 2) “해당 일정만 삭제하시겠어요?” 질문 → 3) 예=해당 인스턴스만 삭제, 아니오=시리즈 전체 삭제 → 4) 저장/확정
- 엣지/에러:
  - 매월 31일, 31일이 없는 달에는 생성 스킵
  - 매년 2/29, 비윤년은 생성 스킵

- 종료 조건은 “종료일 없음(무한)” 또는 “특정 날짜까지”만 지원(“횟수로 제한” 등은 비범위)

## 12. 완료 기준(DoD)

- 반복 유형 4종 동작 및 월/윤년 규칙 검증 통과
- 반복 일정의 겹침 제외가 반영되어 충돌 없이 저장/표시됨
- 캘린더 뷰에서 반복 아이콘이 올바르게 표기/해제됨
- 수정/삭제의 단일/전체 분기 동작이 명세대로 수행됨
- 종료일 선택 시 2025-12-31 상한이 적용됨
