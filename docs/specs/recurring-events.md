# RECURRING-EVENTS: 반복 일정 기능

## 1. 개요

- **목적**: 일정 생성/수정 시 반복 패턴을 설정하고, 반복 일정을 생성·표시·수정·삭제할 수 있는 기능 제공
- **배경**: 정기적인 일정을 효율적으로 관리하기 위해 반복 일정 기능이 필요함
- **용어 사전**:
  - **반복 일정**: 동일한 패턴(매일/매주/매월/매년)으로 반복되는 일정 시리즈
  - **반복 유형**: 매일(daily), 매주(weekly), 매월(monthly), 매년(yearly)
  - **반복 종료일**: 반복 일정이 생성되는 마지막 날짜
  - **단일 수정/삭제**: 반복 일정 중 특정 하나의 일정만 수정/삭제
  - **전체 수정/삭제**: 반복 일정 시리즈 전체를 수정/삭제

## 2. 범위(Scope)

### 포함

- 반복 유형 선택 기능 (매일, 매주, 매월, 매년)
- 반복 종료일 지정 기능 (최대 2025-12-31)
- 반복 일정 생성 로직 (반복 패턴에 따른 일정 인스턴스 생성)
- 반복 일정 표시 (캘린더 뷰에서 아이콘으로 구분)
- 반복 일정 수정 기능 (단일/전체 선택 다이얼로그)
- 반복 일정 삭제 기능 (단일/전체 선택 다이얼로그)

### 제외(명시적 비범위)

- 반복 간격(interval) 설정 UI: interval은 항상 1로 고정되며, 사용자가 변경할 수 없다.
- 반복 일정 겹침 검사: 명세에서 "반복일정은 일정 겹침을 고려하지 않는다"고 명시
- 반복 패턴 복잡한 규칙 (예: "매주 월요일과 수요일", "매월 첫째 주 월요일" 등)

## 3. 요구사항

### 3.1 기능 요구사항(FRs)

#### FR-1: 반복 유형 선택

- **FR-1.1**: 일정 생성 또는 수정 시 반복 유형을 선택할 수 있다.
- **FR-1.2**: 반복 유형 옵션: 매일(daily), 매주(weekly), 매월(monthly), 매년(yearly)
- **FR-1.3**: 매월 선택 시, 시작일이 31일인 경우 매월 마지막 날이 아닌 31일에만 일정을 생성한다.
  - 예: 2025-01-31에 매월 선택 → 2025-01-31, 2025-03-31, 2025-05-31, ... (2월은 31일이 없으므로 건너뜀)
- **FR-1.4**: 매년 선택 시, 윤년 2월 29일에 시작한 경우 29일에만 일정을 생성한다.
  - 예: 2024-02-29에 매년 선택 → 2024-02-29, 2028-02-29, ... (윤년이 아닌 해는 건너뜀)

#### FR-2: 반복 일정 생성

- **FR-2.1**: 반복 유형과 종료일을 기반으로 반복 일정 인스턴스를 생성한다.
- **FR-2.2**: 반복 종료일은 최대 2025-12-31까지 설정 가능하다.
- **FR-2.3**: 반복 일정 생성 시 일정 겹침을 검사하지 않는다.
- **FR-2.4**: 반복 간격(interval)은 항상 1로 고정되며, 사용자가 변경할 수 없다.

#### FR-3: 반복 일정 표시

- **FR-3.1**: 캘린더 뷰(주간/월간)에서 반복 일정에 아이콘을 표시하여 구분한다.
- **FR-3.2**: 반복 일정 아이콘은 반복 유형과 관계없이 동일하게 표시된다.

#### FR-4: 반복 종료일 설정

- **FR-4.1**: 반복 종료 조건으로 "특정 날짜까지" 옵션을 제공한다.
- **FR-4.2**: 반복 종료일 최대값은 2025-12-31이다.

#### FR-5: 반복 일정 수정

- **FR-5.1**: 반복 일정을 수정할 때 "해당 일정만 수정하시겠어요?" 다이얼로그를 표시한다.
- **FR-5.2**: "예" 선택 시 단일 수정:
  - 해당 일정만 수정한다.
  - 제목, 설명, 위치, 카테고리, 날짜, 시간, 알림 시간 등 모든 필드를 수정할 수 있다.
  - 반복 일정 아이콘이 사라진다 (일반 일정으로 변경).
  - 반복 정보(repeat.type)가 'none'으로 변경되고 `repeat.id`가 제거된다.
- **FR-5.3**: "아니오" 선택 시 전체 수정:
  - 반복 일정 시리즈 전체를 수정한다.
  - 제목, 설명, 위치, 카테고리, 시간, 알림 시간 등 필드를 수정할 수 있다.
  - 날짜 변경 시 반복 패턴의 기준일이 변경된다 (새로운 날짜부터 반복 패턴 적용).
  - 반복 일정 아이콘이 유지된다.
  - 반복 정보가 유지된다.

#### FR-6: 반복 일정 삭제

- **FR-6.1**: 반복 일정을 삭제할 때 "해당 일정만 삭제하시겠어요?" 다이얼로그를 표시한다.
- **FR-6.2**: "예" 선택 시 단일 삭제:
  - 해당 일정만 삭제한다.
  - 나머지 반복 일정은 유지된다.
- **FR-6.3**: "아니오" 선택 시 전체 삭제:
  - 반복 일정 시리즈의 모든 일정을 삭제한다.

### 3.2 비기능 요구사항(NFRs)

- **성능**: 반복 일정 생성 시 최대 생성 개수 제한 (2025-12-31까지 고려 시 수천 개 가능)
- **보안/권한**: 기존 일정 권한 정책 유지
- **접근성**: 반복 일정 아이콘에 적절한 aria-label 제공
- **로깅/모니터링**: 반복 일정 생성/수정/삭제 이벤트 로깅 (기존 로깅 정책 유지)

## 4. 사용자 시나리오 & 플로우

### 4.1 반복 일정 생성 시나리오

**해피 패스**:

1. 사용자가 일정 추가 화면에서 반복 일정 체크박스를 선택한다.
2. 반복 유형(매일/매주/매월/매년)을 선택한다.
3. 반복 종료일을 입력한다 (예: 2025-12-31).
4. 일정 정보를 입력하고 저장한다.
5. 시스템이 반복 패턴에 따라 일정 인스턴스들을 생성한다.
6. 캘린더에 반복 일정들이 아이콘과 함께 표시된다.

**엣지 케이스**:

- 31일에 매월 선택: 31일이 없는 월은 건너뛴다.
- 윤년 2월 29일에 매년 선택: 윤년이 아닌 해는 건너뛴다.
- 반복 종료일이 시작일보다 이전: 에러 메시지 표시

### 4.2 반복 일정 수정 시나리오

**해피 패스 - 단일 수정**:

1. 사용자가 캘린더에서 반복 일정 하나를 클릭하여 수정한다.
2. "해당 일정만 수정하시겠어요?" 다이얼로그가 표시된다.
3. "예"를 선택한다.
4. 일정 정보를 수정하고 저장한다.
5. 해당 일정만 수정되고, 반복 일정 아이콘이 사라진다.
6. 나머지 반복 일정은 유지된다.

**해피 패스 - 전체 수정**:

1. 사용자가 캘린더에서 반복 일정 하나를 클릭하여 수정한다.
2. "해당 일정만 수정하시겠어요?" 다이얼로그가 표시된다.
3. "아니오"를 선택한다.
4. 일정 정보를 수정하고 저장한다.
5. 반복 일정 시리즈 전체가 수정된다.
6. 반복 일정 아이콘이 유지된다.

### 4.3 반복 일정 삭제 시나리오

**해피 패스 - 단일 삭제**:

1. 사용자가 캘린더에서 반복 일정 하나를 선택하여 삭제한다.
2. "해당 일정만 삭제하시겠어요?" 다이얼로그가 표시된다.
3. "예"를 선택한다.
4. 해당 일정만 삭제되고, 나머지 반복 일정은 유지된다.

**해피 패스 - 전체 삭제**:

1. 사용자가 캘린더에서 반복 일정 하나를 선택하여 삭제한다.
2. "해당 일정만 삭제하시겠어요?" 다이얼로그가 표시된다.
3. "아니오"를 선택한다.
4. 반복 일정 시리즈의 모든 일정이 삭제된다.

## 5. API/프로토콜

### 5.1 반복 일정 생성

**엔드포인트**: `POST /api/events-list`

**요청 본문**:

```json
{
  "events": [
    {
      "title": "일정 제목",
      "date": "2025-01-31",
      "startTime": "09:00",
      "endTime": "10:00",
      "description": "설명",
      "location": "위치",
      "category": "업무",
      "repeat": {
        "type": "monthly",
        "interval": 1,
        "endDate": "2025-12-31"
      },
      "notificationTime": 10
    }
  ]
}
```

**응답**: 생성된 일정 배열 (각 일정에 `repeat.id` 포함)

### 5.2 반복 일정 수정

**단일 수정**:

- **엔드포인트**: `PUT /api/events/:id`
- **요청 본문**: 수정된 일정 데이터 (repeat.type을 'none'으로 변경)

**전체 수정**:

- **엔드포인트**: `PUT /api/recurring-events/:repeatId`
- **요청 본문**: 수정할 필드들 (title, date, startTime, endTime, description, location, category, notificationTime, repeat 등)
  - 날짜 변경 시 반복 패턴의 기준일이 변경되며, 모든 일정 인스턴스가 재생성될 수 있음

### 5.3 반복 일정 삭제

**단일 삭제**:

- **엔드포인트**: `DELETE /api/events/:id`

**전체 삭제**:

- **엔드포인트**: `DELETE /api/recurring-events/:repeatId`

### 5.4 에러 코드

- `400`: 잘못된 요청 (반복 종료일이 시작일보다 이전, 필수 필드 누락 등)
- `404`: 일정을 찾을 수 없음
- `500`: 서버 내부 오류

## 6. 데이터 모델

### 6.1 타입 정의 변경

```typescript
export interface RepeatInfo {
  type: RepeatType;
  interval: number; // 항상 1로 고정 (사용자가 변경 불가)
  endDate?: string;
  id?: string; // 반복 일정 시리즈 식별자 (서버에서 생성, 선택적 필드)
}
```

**주의사항**:

- `interval`은 타입 정의상 `number`이지만, 실제 사용 시 항상 1로 고정된다.
- `id` 필드는 반복 일정 시리즈에 속한 일정에만 존재하며, 단일 일정에는 없다.
- 기존 일정과의 호환성을 위해 `id`는 선택적 필드로 정의된다.

### 6.2 데이터 구조

- 반복 일정 시리즈의 모든 일정은 동일한 `repeat.id`를 가진다.
- 단일 수정된 일정은 `repeat.type`이 'none'이 되고 `repeat.id`가 제거된다.

## 7. UI/UX

### 7.1 반복 일정 선택 UI

**Material-UI 컴포넌트 활용**:

- `Checkbox`: "반복 일정" 체크박스 (기존과 동일)
- `Select` + `MenuItem`: 반복 유형 선택 드롭다운
  - 매일 (daily)
  - 매주 (weekly)
  - 매월 (monthly)
  - 매년 (yearly)
- `TextField` (type="date"): 반복 종료일 입력 필드
  - `max` 속성: "2025-12-31"
  - `inputProps`: 최대값 제한

**UI 구조**:

- 반복 간격(interval) 입력 필드는 표시하지 않음 (항상 1로 고정)
- 반복 유형 선택은 반복 일정 체크박스가 체크되었을 때만 표시

### 7.2 반복 일정 표시

- 캘린더 뷰(주간/월간)에서 반복 일정 옆에 아이콘 표시
- **Material-UI 아이콘 사용**: `Repeat` 또는 `Loop` 아이콘 (`@mui/icons-material`)
- 아이콘 크기: `fontSize="small"` (일정 제목 옆에 작은 아이콘으로 표시)
- 접근성: `aria-label="반복 일정"` 속성 추가

### 7.3 수정/삭제 다이얼로그

**Material-UI Dialog 컴포넌트 사용**:

**수정 다이얼로그**:

- `DialogTitle`: "일정 수정"
- `DialogContent` + `DialogContentText`: "해당 일정만 수정하시겠어요?"
- `DialogActions` + `Button`:
  - [예] (primary color) - 단일 수정
  - [아니오] (primary color) - 전체 수정
  - [취소] (default) - 취소

**삭제 다이얼로그**:

- `DialogTitle`: "일정 삭제"
- `DialogContent` + `DialogContentText`: "해당 일정만 삭제하시겠어요?"
- `DialogActions` + `Button`:
  - [예] (error color) - 단일 삭제
  - [아니오] (error color) - 전체 삭제
  - [취소] (default) - 취소

### 7.4 에러 메시지

## 부록 B. 확인된 Q&A(사용자 피드백 반영)

### Q1. 반복 간격(interval) 설정은 필요한가요?

**A1**: **interval은 1로 고정**. 사용자가 변경할 수 없으며, UI에도 입력 필드를 제공하지 않는다. `RepeatInfo` 타입에는 `interval: number`로 정의되어 있지만, 실제로는 항상 1의 값을 가진다.

### Q2. 반복 일정 아이콘은 어떤 아이콘을 사용하나요?

**A2**: **Material-UI의 `Repeat` 또는 `Loop` 아이콘 사용** (`@mui/icons-material`). 기존 코드에서 `Notifications` 아이콘을 사용하는 것과 동일한 방식으로 적용한다.

### Q3. 반복 일정 수정 시 시간이나 날짜를 변경할 수 있나요?

**A3**: **시간과 날짜 변경 허용**.

- **단일 수정**: 모든 필드(제목, 날짜, 시간, 설명, 위치, 카테고리, 알림 시간) 수정 가능
- **전체 수정**: 제목, 시간, 설명, 위치, 카테고리, 알림 시간 수정 가능. 날짜 변경 시 반복 패턴의 기준일이 변경되며, 모든 일정 인스턴스가 새 날짜 기준으로 재생성될 수 있음

### Q4. `RepeatInfo`에 `id` 필드를 추가해야 하나요?

**A4**: **추가 필수**. 서버 API에서 `repeat.id`를 사용하여 반복 일정 시리즈를 식별하므로, 타입에 `id?: string` 필드를 추가해야 한다. 기존 일정과의 호환성을 위해 선택적 필드로 정의한다.

### Q5. 반복 일정 생성 시 모든 인스턴스를 한 번에 생성하나요, 아니면 필요할 때 생성하나요?

**A5**: 명세에 명시되지 않음. 서버 API `POST /api/events-list`를 보면 모든 인스턴스를 한 번에 생성하는 것으로 보임. 최대 2025-12-31까지이므로 한 번에 생성하는 것이 합리적.
