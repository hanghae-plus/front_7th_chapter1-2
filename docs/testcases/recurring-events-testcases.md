# 테스트 케이스: 반복 일정 기능

## 통합 테스트 시나리오

### 시나리오 1: 사용자가 매일 반복 일정을 생성할 수 있다
**목적**: 사용자가 UI를 통해 매일 반복 일정을 생성하고 캘린더에 표시되는지 확인

**전제 조건**:
- 캘린더 페이지가 열려 있음
- 현재 날짜는 2025-01-01

**테스트 단계**:
1. '일정 추가' 버튼 클릭
2. 제목 입력: '매일 회의'
3. 날짜 선택: '2025-01-01'
4. 시작 시간 입력: '09:00'
5. 종료 시간 입력: '10:00'
6. '반복 일정' 체크박스 선택
7. 반복 유형 드롭다운에서 '매일' 선택
8. 반복 종료일 선택: '2025-01-07'
9. '저장' 버튼 클릭

**기대 결과**:
- 성공 메시지 '일정이 추가되었습니다.' 표시됨
- 월간 뷰에서 2025-01-01부터 2025-01-07까지 7일간 '매일 회의' 일정이 표시됨
- 각 일정에 MUI Repeat 아이콘이 표시됨
- 일정 목록에 '반복: 1일마다 (종료: 2025-01-07)' 텍스트가 표시됨
- 모든 일정이 동일한 repeatGroupId를 가짐

**참고 파일**: src/__tests__/medium.integration.spec.tsx

### 시나리오 8: 반복 일정의 단일 인스턴스를 수정할 수 있다
**목적**: 사용자가 반복 일정의 특정 날짜 일정만 수정할 수 있는지 확인

**전제 조건**:
- 매일 반복 일정이 이미 생성되어 있음 (2025-01-01 ~ 2025-01-07)
- 제목: '매일 회의'
- 시간: 09:00 - 10:00

**테스트 단계**:
1. 2025-01-03 날짜의 '매일 회의' 일정 수정 버튼 클릭
2. 제목을 '긴급 회의'로 변경
3. 시작 시간을 '10:00'으로 변경
4. 종료 시간을 '11:00'으로 변경
5. '일정 수정' 버튼 클릭
6. "해당 일정만 수정하시겠어요?" 다이얼로그가 표시됨
7. "예" 버튼 클릭

**기대 결과**:
- 성공 메시지 '일정이 수정되었습니다.' 표시됨
- 2025-01-01, 2025-01-02: '매일 회의' 09:00-10:00 유지 (Repeat 아이콘 유지)
- 2025-01-03: '긴급 회의' 10:00-11:00으로 변경 (Repeat 아이콘 사라짐)
- 2025-01-04 ~ 2025-01-07: '매일 회의' 09:00-10:00 유지 (Repeat 아이콘 유지)
- 총 3개의 일정 데이터가 서버에 저장됨:
  - 일정 1: 2025-01-01 ~ 2025-01-02 (기존 반복 일정, endDate 변경됨)
  - 일정 2: 2025-01-03 (단일 일정, repeat.type='none', repeatGroupId 동일)
  - 일정 3: 2025-01-04 ~ 2025-01-07 (새 반복 일정, repeatGroupId 동일)

## 유닛 테스트 작성 시 고려사항

Test First Engineer가 유닛 테스트를 작성할 때 다음 사항을 고려해주세요:

### 필요한 유닛 테스트

1. **generateRecurringDates 함수**
   - 매일 반복 로직 (interval=1로 고정)
   - 매주 반복 로직 (같은 요일에 매주 반복)
   - 매월 반복 로직 (같은 날짜에 매월 반복, 31일 규칙 포함)
   - 매년 반복 로직 (같은 월/일에 매년 반복, 윤년 2/29 규칙 포함)
   - 반복 종료일이 없는 경우 처리
   - 반복 종료일이 있는 경우 처리

2. **validateRecurringConfig 함수**
   - 유효한 반복 설정 검증 (type, interval, startDate)
   - 반복 종료일 검증 (endDate >= startDate)
   - 잘못된 날짜 범위 검증 (endDate < startDate)
   - 필수 필드 누락 검증 (type, interval)

3. **splitRecurringEvent 함수** (단일 일정 수정/삭제 시 사용)
   - 반복 일정 분할 로직 (이전/중간/이후)
   - 수정된 단일 일정 생성 로직
   - 새로운 반복 일정 생성 로직 (수정/삭제 날짜 이후)
   - repeatGroupId 유지 확인

4. **getRepeatText 함수** (반복 정보 텍스트 생성)
   - "반복: 1일마다" 형식
   - "반복: 1주마다" 형식
   - "반복: 1월마다" 형식
   - "반복: 1년마다" 형식
   - 종료일 있을 때: "(종료: YYYY-MM-DD)" 추가
   - 종료일 없을 때: 종료일 정보 없음

5. **expandRecurringEvents 함수** (반복 일정 인스턴스 전개)
   - 반복 일정을 날짜별 인스턴스로 전개
   - 뷰 타입에 맞는 날짜 범위만 전개
   - repeat.type='none'인 일정은 전개하지 않음

6. **useEventOperations 훅 확장**
   - 반복 일정 추가 (repeatGroupId 자동 생성)
   - 단일 일정 수정 (splitRecurringEvent 활용)
   - 전체 일정 수정 (repeatGroupId 기준)
   - 단일 일정 삭제 (splitRecurringEvent 활용)
   - 전체 일정 삭제 (repeatGroupId 기준)

### 경계값 테스트 케이스

- **매월 31일 반복** → 31일이 없는 달(2월, 4월, 6월, 9월, 11월) 건너뛰기
- **매월 29일 반복** → 평년 2월 건너뛰기
- **매월 30일 반복** → 2월 건너뛰기
- **윤년 2월 29일 매년 반복** → 윤년만 표시 (2024, 2028, 2032...)
- **시작일 = 종료일** → 1개 일정만 생성
- **시작일 > 종료일** → 에러 처리
- **interval = 0 또는 음수** → 에러 처리 (interval은 항상 1로 고정)
- **반복 종료일 없음** → 무한 반복 (endDate=undefined)

예상 결과:

### 특수 날짜 처리 로직

**매월 31일 반복 규칙**:
- 31일이 있는 달: 1월, 3월, 5월, 7월, 8월, 10월, 12월
- 31일이 없는 달: 2월(28/29일), 4월(30일), 6월(30일), 9월(30일), 11월(30일)
- 처리 방법: 31일이 없는 달은 건너뛰고 다음 달로 이동

**윤년 2월 29일 매년 반복 규칙**:
- 윤년 판별: year % 4 === 0 && (year % 100 !== 0 || year % 400 === 0)
- 윤년: 2024, 2028, 2032, ...
- 평년: 2025, 2026, 2027, 2029, ...
- 처리 방법: 평년에는 건너뛰고 다음 해로 이동

### 반복 일정 아이콘 표시 조건

- repeat.type !== 'none'인 경우 MUI Repeat 아이콘 표시
- 단일 일정으로 분할된 일정(repeat.type='none')은 아이콘 미표시
- 아이콘 위치: 일정 제목 왼쪽

### repeatGroupId 관리

- 반복 일정 생성 시: uuid 또는 timestamp 기반으로 고유 ID 자동 생성
- 단일 일정 수정/삭제 시: 원본의 repeatGroupId를 모든 분할된 일정에 유지
- 전체 일정 수정/삭제 시: repeatGroupId로 모든 관련 일정 조회 및 처리
