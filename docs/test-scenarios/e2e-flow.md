# E2E 테스트 시나리오 문서

## 개요

이 문서는 캘린더 애플리케이션의 E2E 테스트 시나리오를 Given-When-Then 형식으로 정의합니다.

**목표**: 실제 사용자 관점에서 애플리케이션의 핵심 워크플로우를 검증하는 E2E 테스트 시나리오를 설계합니다.

---

## 시나리오 1: 일정 추가 (Event Creation) 🎯

### SC-001: 기본 일정 추가 (Happy Path)

**Given-When-Then**:

```
Given: 사용자가 캘린더 페이지에 접속함
 And: 폼이 비어있는 초기 상태임
When: 사용자가 다음 정보를 입력함
  - 제목: "팀 미팅"
  - 날짜: "2024-01-15"
  - 시작 시간: "10:00"
  - 종료 시간: "11:00"
  - 설명: "프로젝트 진행 상황 논의"
  - 위치: "회의실 A"
  - 카테고리: "업무"
 And: "일정 추가" 버튼을 클릭함
Then: 일정이 성공적으로 저장됨
 And: 일정 리스트에 새 일정이 표시됨
 And: 썡(Snackbar) 알림에 성공 메시지가 표시됨
 And: 폼이 초기화됨
```

**예상 테스트 코드**:

```typescript
test('기본 일정을 추가할 수 있다', async ({ page }) => {
  await page.goto('/');

  await page.fill('#title', '팀 미팅');
  await page.fill('#date', '2024-01-15');
  await page.fill('#start-time', '10:00');
  await page.fill('#end-time', '11:00');
  await page.fill('#description', '프로젝트 진행 상황 논의');
  await page.fill('#location', '회의실 A');
  await page.selectOption('#category', { label: '업무' });

  await page.click('[data-testid="event-submit-button"]');

  await expect(page.locator('[data-testid="event-list"]')).toContainText('팀 미팅');
  await expect(page.locator('text=일정이 저장되었습니다')).toBeVisible();
});
```

**검증 포인트**:

- ✅ 모든 필수 필드가 유효함
- ✅ 일정 리스트에 추가됨
- ✅ 성공 메시지 표시됨
- ✅ 폼이 초기화됨

### SC-002: 필수 필드 누락 시 에러 처리

**Given-When-Then**:

```
Given: 사용자가 캘린더 페이지에 접속함
When: 사용자가 필수 필드(제목, 날짜, 시작/종료 시간) 없이
      "일정 추가" 버튼을 클릭함
Then: 에러 스낵바가 표시됨
 And: "필수 정보를 모두 입력해주세요." 메시지가 노출됨
 And: 일정이 저장되지 않음
 And: 폼 입력값이 유지됨
```

**검증 포인트**:

- ✅ "필수 정보를 모두 입력해주세요." 에러 메시지
- ✅ 일정이 추가되지 않음
- ✅ 페이지가 리로드되지 않음

---

### SC-003: 시간 유효성 검증

**Given-When-Then**:

```
Given: 사용자가 캘린더 페이지에 접속함
 And: 제목과 날짜를 입력함
When: 사용자가 종료 시간이 시작 시간보다 빠르게 입력함
  - 시작 시간: "14:00"
  - 종료 시간: "10:00"
 And: 종료 시간 필드에서 포커스를 벗어남 (onBlur)
Then: 시간 에러 메시지가 표시됨
 And: "종료 시간은 시작 시간보다 늦어야 합니다." 메시지가 표시됨
 And: "일정 추가" 버튼은 비활성화됨
```

**검증 포인트**:

- ✅ 시간 유효성 검증 동작
- ✅ 에러 메시지가 Tooltip으로 표시됨
- ✅ 잘못된 입력 시 저장 불가

## 시나리오 2: 일정 충돌 감지 (Overlap Detection) 🔔

### SC-004: 겹치는 일정 추가 시 경고 표시

**Given-When-Then**:

```
Given: 이미 다음과 같은 일정이 존재함
  - 제목: "기존 회의"
  - 날짜: "2024-01-15"
  - 시간: "10:00 - 11:00"
When: 사용자가 겹치는 시간의 새 일정을 추가 시도함
  - 제목: "새로운 미팅"
  - 날짜: "2024-01-15"
  - 시간: "10:30 - 11:30"
 And: "일정 추가" 버튼을 클릭함
Then: 충돌 경고 다이얼로그가 표시됨
 And: 경고 메시지에 "일정 겹침 경고" 타이틀이 표시됨
 And: 다음 충돌 일정 목록이 표시됨
  - "기존 회의 (2024-01-15 10:00-11:00)"
 And: "취소"와 "계속 진행" 버튼이 표시됨
```

**검증 포인트**:

- ✅ 충돌 감지 로직 동작
- ✅ 다이얼로그에 충돌 일정 정보 표시
- ✅ 사용자 선택 대기

---

### SC-005: 충돌 경고 후 강제 저장

**Given-When-Then**:

```
Given: 충돌 경고 다이얼로그가 표시된 상태
When: 사용자가 "계속 진행" 버튼을 클릭함
Then: 일정이 강제로 저장됨
 And: 다이얼로그가 닫힘
 And: 두 일정이 모두 일정 리스트에 표시됨
```

**검증 포인트**:

- ✅ 강제 저장 기능 동작
- ✅ 다이얼로그 닫힘
- ✅ 충돌 일정들이 모두 표시됨

---

### SC-006: 충돌 경고 후 취소

**Given-When-Then**:

```
Given: 충돌 경고 다이얼로그가 표시된 상태
When: 사용자가 "취소" 버튼을 클릭함
Then: 다이얼로그가 닫힘
 And: 일정이 저장되지 않음
 And: 원래 입력한 폼 데이터가 유지됨
```

**검증 포인트**:

- ✅ 취소 기능 동작
- ✅ 일정이 저장되지 않음
- ✅ 폼 데이터 유지

## 시나리오 3: 일정 수정 (Event Editing) ✏️

### SC-007: 기존 일정 수정

**Given-When-Then**:

```
Given: 다음과 같은 일정이 존재함
  - 제목: "팀 미팅"
  - 날짜: "2024-01-15"
  - 시간: "10:00 - 11:00"
When: 사용자가 일정 리스트에서 해당 일정의 "수정" 버튼을 클릭함
Then: 폼이 해당 일정 정보로 자동 채워짐
 And: 폼 타이틀이 "일정 수정"으로 변경됨
When: 사용자가 제목을 "팀 미팅 (확정)"으로 수정함
 And: "일정 수정" 버튼을 클릭함
Then: 수정된 일정이 저장됨
 And: 일정 리스트에 변경된 제목이 표시됨
 And: "일정이 수정되었습니다." 메시지가 표시됨
```

**검증 포인트**:

- ✅ 폼 자동 채우기 동작
- ✅ 수정 기능 정상 동작
- ✅ 성공 메시지 표시

## 시나리오 5: 검색 기능 (Search Flow) 🔍

### SC-009: 검색어로 일정 필터링

**Given-When-Then**:

```
Given: 다음과 같은 일정들이 존재함
  - "팀 미팅" (2024-01-15)
  - "장보기" (2024-01-16)
  - "프로젝트 회의" (2024-01-17)
When: 사용자가 검색 필드에 "팀"을 입력함
Then: 검색 결과에 "팀 미팅"만 표시됨
 And: "장보기"와 "프로젝트 회의"는 표시되지 않음
```

**검증 포인트**:

- ✅ 검색 기능 동작
- ✅ 부분 일치 검색
- ✅ 실시간 필터링

## 시나리오 8: 접근성 (Accessibility) ♿

### SC-016: 키보드 네비게이션

**Given-When-Then**:

```
Given: 사용자가 캘린더 페이지에 접속함
When: 사용자가 Tab 키를 눌러 네비게이션함
Then: 포커스가 다음 요소들로 이동함
  - 폼 제목 필드
  - 날짜 필드
  - 시작/종료 시간 필드
  - 버튼들
 And: 각 요소에 포커스가 시각적으로 표시됨
 And: Enter 키로 버튼 클릭 가능
```

**검증 포인트**:

- ✅ 키보드 네비게이션 동작

### SC-017: ARIA 레이블 확인

**Given-When-Then**:

```
Given: 캘린더 페이지가 로드됨

 And: 스크린 리더 사용자가 모든 기능을 이해할 수 있음
```

**검증 포인트**:

- ✅ ARIA 속성 존재
- ✅ 접근성 준수

## Edge Cases

### EC-001: 자정을 넘어가는 일정

```
Given: 사용자가 "23:00"부터 "01:00"까지의 일정을 추가
Then: 시간 유효성 검증이 올바르게 처리됨
```

### EC-002: 장기 일정 (8시간 이상)

```
Given: 사용자가 "09:00"부터 "18:00"까지의 일정을 추가
Then: 일정이 정상적으로 저장되고 표시됨
```

### EC-003: 같은 시간대 여러 일정

```
Given: 동일한 시간에 3개의 충돌 일정 추가
Then: 모든 충돌이 감지되고 경고 메시지에 모두 표시됨
```
