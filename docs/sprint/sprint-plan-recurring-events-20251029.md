# Sprint Plan: 반복 일정 기능

- 버전: v2.0.0

## 목표

반복 일정 생성, 수정(단일/전체), 삭제(단일/전체) 기능을 테스트 주도 개발(TDD) 방식으로 구현하고, 캘린더에 MUI Repeat 아이콘과 함께 표시한다. 특수 날짜 처리(매월 31일, 윤년 2월 29일) 규칙을 포함하며, 반복 종료일은 2025년 12월 31일을 초과할 수 없다.

## 마일스톤

- QA Engineer가 반복 일정 기능에 대한 테스트 케이스를 작성한다
  - 완료 조건: 생성/수정/삭제 시나리오, 4가지 반복 유형(매일/매주/매월/매년), 특수 날짜 예외 처리, 단일/전체 분기 로직에 대한 테스트 케이스 포함
- Test First Engineer가 테스트 케이스를 바탕으로 RED 테스트를 작성한다
  - 완료 조건: 모든 테스트 케이스가 실패하는 단위 테스트와 통합 테스트 작성 완료
- Implementation Engineer가 RED 테스트를 통과시키는 로직을 구현한다
  - 완료 조건: 모든 테스트가 통과하며, 반복 일정 생성/수정/삭제 기능이 정상 동작
- Refactoring Engineer가 구현된 코드를 리팩토링한다
  - 완료 조건: 코드 중복 제거, 함수 분리, 성능 최적화 완료하며 모든 테스트 통과 유지

## 작업 목록

- [ ] 반복 일정 데이터 모델 설계 (Event 타입에 repeat, repeatGroupId 추가)
- [ ] 반복 유형 선택 UI 구현 (체크박스, 드롭다운, 종료일 입력)
- [ ] 반복 일정 생성 로직 구현 (repeatGroupId 자동 생성)
- [ ] 반복 일정 표시 로직 구현 (날짜별 인스턴스 계산)
- [ ] 특수 날짜 처리 (매월 31일, 윤년 2월 29일)
- [ ] MUI Repeat 아이콘 표시 (주간/월간 뷰, 일정 목록)
- [ ] 반복 정보 텍스트 표시 ("반복: 1일마다", 종료일)
- [ ] 반복 일정 수정 다이얼로그 구현 (단일/전체 선택)
- [ ] 단일 일정 수정 로직 (분할: 이전/수정된 단일/이후)
- [ ] 전체 일정 수정 로직 (repeatGroupId 기준)
- [ ] 반복 일정 삭제 다이얼로그 구현 (단일/전체 선택)
- [ ] 단일 일정 삭제 로직 (분할: 이전/이후)
- [ ] 전체 일정 삭제 로직 (repeatGroupId 기준)
- [ ] 반복 종료일 검증 (≥ 시작일)
