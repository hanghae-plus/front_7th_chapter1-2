# PRD: 반복 일정 기능

- 버전: v5

## 1. 배경과 문제 정의

현재 반복 일정 수정 시 사용자가 수정 내용을 입력한 후 제출 버튼을 클릭해야만 단일/전체 수정 선택 다이얼로그가 표시됩니다. 이는 사용자가 단일 수정을 원하는 경우 불필요하게 반복 설정을 입력해야 하는 불편함이 있습니다. 수정 버튼 클릭 시점에 단일/전체 수정 의도를 먼저 확인하고, 이에 따라 폼의 반복 설정 상태를 자동으로 조정하여 사용자 경험을 개선합니다.

## 2. 목표

- 반복 일정 수정 UX 개선
- 불필요한 반복 설정 입력 단계 제거
- 사용자 의도에 맞는 폼 상태 자동 설정

## 3. 범위

### 포함 범위

- 반복 일정 수정 버튼 클릭 시 단일/전체 선택 다이얼로그 표시
- 다이얼로그 선택 결과에 따른 폼 상태 자동 설정
- 폼 제출 시 반복 일정 체크박스 상태 기반 로직 분기
- 단일 수정 시 splitRecurringEvent 로직 적용

### 제외 범위

- 반복 일정 삭제 로직 변경
- 기존 반복 일정 생성 로직 변경
- 반복 일정 표시 로직 변경

## 4. 사용자 시나리오

### 사용자 시나리오

#### 반복 일정 수정 (변경사항)

##### 수정 버튼 클릭 시점

- 사용자가 일정 리스트에서 반복 일정의 수정 버튼을 클릭하면 "해당 일정만 수정하시겠어요?" 다이얼로그가 표시된다
- "해당 일정만 수정하시겠어요?" 다이얼로그에는 "예" 버튼과 "아니오" 버튼이 표시된다
- 다이얼로그의 "예" 버튼은 단일 일정 수정을 의미한다
- 다이얼로그의 "아니오" 버튼은 전체 반복 일정 수정을 의미한다

##### 단일 일정 수정 선택 시

- "예" 버튼을 클릭하면 일정 수정 폼이 표시된다
- 일정 수정 폼의 "반복 일정" 체크박스가 자동으로 해제된 상태로 표시된다
- 반복 설정 UI (반복 유형, 반복 종료일)가 숨겨진 상태로 표시된다
- 사용자는 수정할 내용을 입력한다
- 사용자가 "일정 수정" 버튼을 클릭하면 별도의 다이얼로그 없이 즉시 처리된다
- 단일 일정 수정 시 `splitRecurringEvent` 함수를 사용하여 반복 일정을 분할한다
- 원본 반복 일정이 삭제되고, before 반복 일정, 수정된 단일 일정, after 반복 일정이 생성된다
- before 반복 일정은 원본의 시작일부터 수정 날짜 이전 마지막 반복 날짜까지이다
- 수정된 단일 일정은 repeat.type이 'none'으로 설정된다
- after 반복 일정은 수정 날짜 다음 반복 날짜부터 원본의 종료일까지이다
- 수정 날짜가 반복 일정의 첫 날인 경우 before 반복 일정은 생성되지 않는다
- 수정 날짜가 반복 일정의 마지막 날인 경우 after 반복 일정은 생성되지 않는다
- 단일 일정 수정 후 "일정이 수정되었습니다." 메시지가 표시된다

##### 전체 반복 일정 수정 선택 시

- "아니오" 버튼을 클릭하면 일정 수정 폼이 표시된다
- 일정 수정 폼의 "반복 일정" 체크박스가 자동으로 선택된 상태로 표시된다
- 반복 설정 UI (반복 유형, 반복 종료일)가 표시된다
- 기존 반복 설정 값(반복 유형, 반복 간격, 반복 종료일)이 폼에 자동으로 채워진다
- 사용자는 수정할 내용을 입력한다
- 사용자는 필요한 경우 반복 설정도 변경할 수 있다
- 사용자가 "일정 수정" 버튼을 클릭하면 별도의 다이얼로그 없이 즉시 처리된다
- 전체 반복 일정 수정 시 기존 반복 일정의 모든 필드가 업데이트된다
- 반복 정보(repeat.type, repeat.interval, repeat.endDate)가 유지 또는 업데이트된다
- 전체 반복 일정 수정 후 "일정이 수정되었습니다." 메시지가 표시된다

##### 일반 일정 수정 (반복 일정이 아닌 경우)

- 사용자가 일정 리스트에서 일반 일정의 수정 버튼을 클릭하면 다이얼로그 없이 바로 일정 수정 폼이 표시된다
- 일정 수정 폼의 "반복 일정" 체크박스가 해제된 상태로 표시된다
- 사용자는 필요한 경우 "반복 일정" 체크박스를 선택하여 반복 일정으로 변경할 수 있다
- 사용자가 "일정 수정" 버튼을 클릭하면 반복 일정 체크박스 상태에 따라 처리된다
- 체크박스가 해제되어 있으면 일반 일정 수정으로 처리된다
- 체크박스가 선택되어 있으면 일반 일정에서 반복 일정으로 변경되어 처리된다

#### 반복 일정 삭제 (기존 유지)

- 사용자가 반복 일정의 삭제 버튼을 클릭하면 "해당 일정만 삭제하시겠어요?" 다이얼로그가 표시된다
- "해당 일정만 삭제하시겠어요?" 다이얼로그에는 "예" 버튼과 "아니오" 버튼이 표시된다
- "해당 일정만 삭제하시겠어요?" 다이얼로그에서 "예" 버튼을 클릭하면 반복 일정이 분할되고 해당 날짜의 일정만 제외된다
- 단일 일정 삭제 시 `splitRecurringEvent` 함수를 사용하여 반복 일정을 분할한다
- 원본 반복 일정이 삭제되고, before 반복 일정과 after 반복 일정이 생성된다
- 단일 일정 삭제 시 생성된 새 반복 일정의 시작일은 삭제 날짜의 다음 반복 날짜이다
- 단일 일정 삭제 시 생성된 새 반복 일정의 endDate는 원본의 endDate와 동일하다
- 단일 일정 삭제 시 생성된 새 반복 일정의 repeatGroupId는 원본과 동일하다
- "해당 일정만 삭제하시겠어요?" 다이얼로그에서 "아니오" 버튼을 클릭하면 같은 repeatGroupId를 가진 모든 일정이 삭제된다
- 전체 일정 삭제 시 같은 repeatGroupId를 가진 모든 반복 일정과 단일 일정이 삭제된다

### 구현 요구사항

#### 상태 관리

- 반복 일정 수정 다이얼로그 오픈 상태를 관리하는 `isRecurringEditDialogOpen` state
- 대상 반복 일정을 저장하는 `targetEventForEdit` state
- Edit 버튼 클릭 시 대상 이벤트의 `repeat.type !== 'none'` 여부 확인

#### 다이얼로그 처리

- "예" 버튼 클릭 시:
  - `editEvent(event)` 호출하되 `isRepeating`을 `false`로 설정
  - 반복 설정 UI를 숨김
- "아니오" 버튼 클릭 시:
  - `editEvent(event)` 호출하되 `isRepeating`을 `true`로 유지
  - 반복 설정 UI를 표시하고 기존 값 채우기

#### 폼 제출 처리

- `addOrUpdateEvent` 함수에서 반복 일정 체크박스 상태만 확인
- 체크박스가 해제되어 있고 원본이 반복 일정이었다면:
  - `splitRecurringEvent` 사용하여 분할
  - before, 수정된 단일 일정, after 저장
- 체크박스가 선택되어 있으면:
  - 기존 반복 일정 업데이트
  - 반복 정보 유지 또는 업데이트
