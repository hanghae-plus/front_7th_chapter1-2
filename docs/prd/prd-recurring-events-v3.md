# PRD: 반복 일정 기능

- 버전: v3

## 1. 배경과 문제 정의

현재 일정 관리 시스템에서 반복되는 일정을 매번 수동으로 생성해야 하는 불편함이 있습니다. 사용자가 매일, 매주, 매월, 매년 반복되는 일정을 한 번에 설정하고 관리할 수 있는 기능을 추가하여 사용자 편의성을 향상시킵니다.

## 2. 목표

- 반복 일정 생성 기능 추가
- 반복 일정 수정 기능 추가 (단일/전체 선택)
- 반복 일정 삭제 기능 추가 (단일/전체 선택)
- 반복 일정 시각적 표시

## 3. 범위

### 포함 범위

- 반복 유형 선택 UI (매일, 매주, 매월, 매년)
- 반복 종료 조건 설정 (특정 날짜까지 - 선택 사항)
- 반복 일정 아이콘 표시 (MUI Repeat 아이콘)
- 반복 일정 수정 시 단일/전체 선택 다이얼로그
- 반복 일정 삭제 시 단일/전체 선택 다이얼로그
- 특수 날짜 처리 (31일 매월, 윤년 29일 매년)
- 반복 일정 그룹 관리 (repeatGroupId)

### 제외 범위

- 반복 일정 겹침 검사
- 반복 간격 커스터마이징 (항상 1로 고정)
- 특정 요일 선택 기능 (예: 매주 월요일과 수요일만)
- 복잡한 반복 패턴 (예: 매월 마지막 금요일)

## 4. 사용자 시나리오

### 사용자 시나리오

- 사용자는 일정 생성 시 "반복 일정" 체크박스를 선택할 수 있다
- 사용자는 일정 수정 시 "반복 일정" 체크박스를 선택할 수 있다
- "반복 일정" 체크박스를 선택하면 반복 설정 UI가 표시된다
- 반복 설정 UI에는 반복 유형 선택 드롭다운이 포함된다
- 반복 설정 UI에는 반복 종료일 입력 필드가 포함된다
- 사용자는 반복 유형 드롭다운에서 "매일", "매주", "매월", "매년" 중 하나를 선택할 수 있다
- 반복 간격은 항상 1로 고정되어 UI에 표시되지 않는다
- 사용자는 반복 종료일을 선택할 수 있다
- 반복 종료일은 선택 사항이며, 선택하지 않으면 무한 반복된다
- 반복 종료일을 선택하는 경우 2025년 12월 31일을 초과할 수 없다
- 반복 종료일을 선택하는 경우 일정 시작일 이후 날짜여야 한다
- 31일에 "매월" 반복을 선택하면 31일이 있는 달에만 일정이 표시된다
- 31일이 없는 달은 2월, 4월, 6월, 9월, 11월이다
- 윤년 2월 29일에 "매년" 반복을 선택하면 윤년에만 일정이 표시된다
- 평년 2월 29일에 "매년" 반복을 선택하는 경우 평년에는 일정이 표시되지 않는다
- 반복 일정은 일정 겹침 검사를 하지 않는다
- 사용자가 일정 추가 버튼을 클릭하면 반복 일정이 생성된다
- 반복 일정 생성 시 서버에는 반복 정보만 저장되며, 각 날짜별로 데이터가 저장되지 않는다
- 반복 일정 생성 시 고유한 repeatGroupId가 자동으로 생성된다
- 캘린더의 주간 뷰에서 반복 일정에 MUI Repeat 아이콘이 표시된다
- 캘린더의 월간 뷰에서 반복 일정에 MUI Repeat 아이콘이 표시된다
- Repeat 아이콘은 일정 제목 왼쪽에 표시된다
- 일정 목록에서 반복 일정에 MUI Repeat 아이콘이 표시된다
- 일정 목록에서 반복 정보가 텍스트로 표시된다
- 반복 정보 텍스트 형식은 "반복: 1일마다" 또는 "반복: 1주마다" 또는 "반복: 1월마다" 또는 "반복: 1년마다"이다
- 반복 종료일이 설정된 경우 "(종료: YYYY-MM-DD)" 형식으로 추가 표시된다
- 사용자가 반복 일정의 수정 버튼을 클릭하면 일정 수정 폼이 표시된다
- 사용자가 일정 수정 폼에서 내용을 수정한 후 "일정 수정" 버튼을 클릭하면 "해당 일정만 수정하시겠어요?" 다이얼로그가 표시된다
- "해당 일정만 수정하시겠어요?" 다이얼로그에는 "예" 버튼과 "아니오" 버튼이 표시된다
- "해당 일정만 수정하시겠어요?" 다이얼로그에서 "예" 버튼을 클릭하면 반복 일정이 분할되고 해당 날짜의 일정만 수정된다
- 단일 일정 수정 시 기존 반복 일정의 endDate가 수정 날짜 이전의 마지막 반복 날짜로 변경된다
- 단일 일정 수정 시 수정된 내용으로 새로운 단일 일정이 생성된다
- 단일 일정 수정 시 생성된 단일 일정의 repeat.type은 'none'이다
- 단일 일정 수정 시 생성된 단일 일정의 repeatGroupId는 원본과 동일하다
- 단일 일정 수정 시 수정 날짜 이후의 날짜부터 시작하는 새로운 반복 일정이 생성된다
- 단일 일정 수정 시 생성된 새 반복 일정의 시작일은 수정 날짜의 다음 반복 날짜이다
- 단일 일정 수정 시 생성된 새 반복 일정의 endDate는 원본의 endDate와 동일하다
- 단일 일정 수정 시 생성된 새 반복 일정의 repeatGroupId는 원본과 동일하다
- 단일 일정 수정 후 해당 일정의 Repeat 아이콘이 사라진다
- "해당 일정만 수정하시겠어요?" 다이얼로그에서 "아니오" 버튼을 클릭하면 같은 repeatGroupId를 가진 모든 일정이 수정된다
- 전체 일정 수정 시 반복 정보가 유지된다
- 전체 일정 수정 시 모든 일정의 Repeat 아이콘이 유지된다
- 사용자가 반복 일정의 삭제 버튼을 클릭하면 "해당 일정만 삭제하시겠어요?" 다이얼로그가 표시된다
- "해당 일정만 삭제하시겠어요?" 다이얼로그에는 "예" 버튼과 "아니오" 버튼이 표시된다
- "해당 일정만 삭제하시겠어요?" 다이얼로그에서 "예" 버튼을 클릭하면 반복 일정이 분할되고 해당 날짜의 일정만 제외된다
- 단일 일정 삭제 시 기존 반복 일정의 endDate가 삭제 날짜 이전의 마지막 반복 날짜로 변경된다
- 단일 일정 삭제 시 삭제 날짜 이후의 날짜부터 시작하는 새로운 반복 일정이 생성된다
- 단일 일정 삭제 시 생성된 새 반복 일정의 시작일은 삭제 날짜의 다음 반복 날짜이다
- 단일 일정 삭제 시 생성된 새 반복 일정의 endDate는 원본의 endDate와 동일하다
- 단일 일정 삭제 시 생성된 새 반복 일정의 repeatGroupId는 원본과 동일하다
- "해당 일정만 삭제하시겠어요?" 다이얼로그에서 "아니오" 버튼을 클릭하면 같은 repeatGroupId를 가진 모든 일정이 삭제된다
- 전체 일정 삭제 시 같은 repeatGroupId를 가진 모든 반복 일정과 단일 일정이 삭제된다
