# PRD: 반복 일정 기능

- 버전: v1.0.0

## 1. 배경과 문제 정의

캘린더 사용자는 주기적으로 반복되는 일정(회의, 결제일 등)을 손쉽게 생성/관리하길 원한다. 현재 시스템에는 반복 일정이 없어 동일 일정을 수동으로 여러 번 등록해야 하며, 수정/삭제 시에도 일괄 처리가 불가능하다. 이에 반복 일정 생성/표시/수정/삭제 전 과정을 지원하는 기능이 필요하다.

## 2. 목표와 성공 지표

- 반복 일정 생성/표시/수정/삭제 기능 제공
- 성공 지표
  - 반복 일정 생성·수정·삭제 플로우 성공률 ≥ 99%
  - 반복 일정 표시 정확도(아이콘/인스턴스 반영) ≥ 99%

## 3. 범위

### 포함 범위

- 반복 유형 선택: 일정 생성 또는 수정 시 반복 유형 지정
- 유형: 매일, 매주, 매월, 매년
- 예외 규칙
  - 매월 31일 선택 시: 31일이 있는 달에만 생성(마지막 날 치환 금지)
  - 매년 윤년 2/29 선택 시: 2/29에만 생성(비윤년에는 미생성)
- 반복일정은 겹침 무시(중복 허용)
- 캘린더 뷰 반복 아이콘 표시(반복 인스턴스 구분)
- 반복 종료 조건: 특정 날짜까지(최대 2025-12-31)
- 반복 일정 수정
  - 단일 수정: 해당 인스턴스만 단일 일정으로 변경, 반복 아이콘 제거
  - 전체 수정: 모든 인스턴스에 적용, 반복 아이콘 유지
- 반복 일정 삭제
  - 단일 삭제: 해당 인스턴스만 삭제
  - 전체 삭제: 모든 인스턴스 삭제

### 제외 범위

- 외부 캘린더 연동/동기화
- 모바일 전용 리디자인 및 대규모 UI 개편

## 4. 사용자 시나리오 / 요구사항

### 사용자 시나리오

- 사용자는 회의 일정을 매주 반복으로 등록하고, 특정 회의만 시간 변경(단일 수정)한다.
- 사용자는 결제일을 매월 31일로 등록하고, 31일이 없는 달에는 생성되지 않길 원한다.
- 사용자는 윤년 생일(2/29)을 매년 반복으로 등록하며, 비윤년에는 일정이 생기지 않길 원한다.
- 사용자는 캘린더에서 반복 인스턴스를 아이콘으로 쉽게 구분하길 원한다.

### 기능 요구사항

- 반복 유형: 매일/매주/매월/매년 중 하나 선택 가능
- 매월 31일: 31일 존재 달에만 인스턴스 생성
- 매년 2/29: 윤년에만 인스턴스 생성
- 캘린더 표시: 반복 인스턴스에 반복 아이콘 표시
- 종료 조건: 특정 날짜까지(≤ 2025-12-31)
- 수정
  - 단일: 해당 인스턴스만 단일 일정으로 변경, 반복 아이콘 제거
  - 전체: 모든 인스턴스에 변경사항 반영, 반복 아이콘 유지
- 삭제
  - 단일: 해당 인스턴스만 삭제
  - 전체: 모든 인스턴스 삭제
- 겹침 정책: 반복일정은 겹침을 고려하지 않음(중복 허용)

### 비기능 요구사항

- 캘린더 렌더링 시 반복 인스턴스 표시 지연 p95 ≤ 300ms(월간 뷰 기준 내부 연산)
- 수정/삭제 동작은 UI 상 명확한 확인 텍스트로 안내(오동작 방지)

## 5. 데이터/설계 고려사항

- 반복 규칙 표현
  - 유형, 간격(필요 시 확장), 종료일, 예외 규칙(31일/2월29일)을 포함하는 구조 설계
- 인스턴스 생성 전략
  - 뷰 포트 기준 가시 구간만 계산/표시(전체 미리 생성 지양)
  - 31일/2월29일 규칙은 생성 로직단에서 필터링
- 식별 및 수정·삭제 전략
  - 반복 마스터(시리즈) ID와 인스턴스 식별자 설계
  - 단일 수정 시 해당 인스턴스를 분리(단일 일정으로 변환)하고 반복 아이콘 제거
  - 전체 수정 시 마스터 규칙 변경 후 가시 구간 재생성/갱신
- 표시
  - 반복 인스턴스에 일관된 아이콘 적용, 단일 전환 시 제거
- 경계/예외 테스트 케이스 권장
  - 매월 31일 케이스(2/4/6/9/11월 미생성 확인)
  - 윤년/비윤년 2/29 케이스
  - 단일/전체 수정·삭제 플로우 확인
