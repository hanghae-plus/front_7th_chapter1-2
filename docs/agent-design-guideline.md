## 🧩 [Agent 이름]

| 항목 | 내용 |
|------|------|
| **목적 (Goal)** | ex. 명세를 분석하고 테스트 설계용 문서로 구체화한다. |
| **입력 (Input)** | ex. request/feature.md, 프로젝트 구조 정보 |
| **출력 (Output)** | ex. log/{date}/spec.md |
| **제약 (Constraints)** | ex. 새로운 기능 추가 금지, Markdown 계층 구조 준수 |
| **출력 형식 (Output Format)** | ex. Markdown, 구조: `# 기능 > ## 시나리오 > ### 입력/출력` |
| **참고 문서 (References)** | ex. product PRD 문서, 기존 모듈 설명서 |
| **후속 단계 (Next Agent)** | ex. Test Designer Agent |
| **실행 조건 (Execution Condition)** | ex. 기능 요청 시 자동 실행, 명세 파일 변경 시 |

### 세부 동작 규칙
- ✅ 단계별 작업 절차:
  1. 명세 파일을 분석하여 기능 요구사항 추출  
  2. 각 요구사항을 테스트 가능 단위로 분해  
  3. 결과를 계층적 Markdown으로 정리  
  4. “이 명세가 기존 기능에 미치는 영향” 섹션을 반드시 포함
- ✅ 출력 검증 기준:
  - 결과 문서에 `기능명`, `입력`, `출력`, `예외 조건`이 모두 포함되어야 함  
  - Markdown 구조가 파싱 가능한 형태여야 함  
  - 다음 Agent(Test Designer)가 참조 가능한 링크 형식 포함

### 예시 출력 (샘플)
```md
# 일정 반복 생성 기능 명세
## 기능 요약
- 사용자는 일정 생성 시 반복 옵션을 선택할 수 있다.
## 시나리오
- 매일 반복 선택 시 하루마다 새로운 일정 생성
- 31일 존재하지 않는 달의 처리 로직 포함
## 입력/출력
| 입력 | 출력 |
|------|------|
| 반복 유형: daily | 생성된 일정 배열 |
